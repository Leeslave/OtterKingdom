## 2. 수치 (모두 `Assets/Editor/Settlement/SettlementSetup.cs` 표 → 에셋)

| 부탁 | 조건 | 비용 | 시간 | 완료하면 |
|---|---|---|---|---|
| 첫 번째 집 만들기 | 처음부터 | 목재 8, 돌 5 (새 게임 시작 재료와 같음) | 10초 (짧은 연출, 몽실이가 직접 지음) | 파란 집, 몽실 주민(1명), 물감이(정착 후보)·꾸벅이(방문)·뚝딱이(건설 해달) 도착, 단계 1 |
| 새 이웃의 집 | 첫 집 | 골드 150, 목재 12, 돌 8 | 30초 (건설 해달) | 빨간 집, 물감이·뚝딱이 주민 → **주민 3명**, 단계 2 |
| 먹거리를 길러요 (농경지 개간) | 주민 3명 | 골드 200, 목재 10, 돌 10 | 45초 (건설 해달) | 위쪽 길의 잡목·돌 치움, **밭 해금**, 요정 상점 등장, 단계 3 |

- 단계 이름: 빈터 → 첫 정착 → 작은 정착지 → 자급 시작
- 건설은 끝나는 시각(UTC)을 저장하므로 게임을 꺼 둔 동안에도 진행된다.
- 공사 과정이 보인다: 집은 건설 예정지 → 골조 → 벽 → 마무리(발판·사다리) 단계 그림이 진행도 15%·45%·80%에서 바뀌고(바뀔 때 통 튀며 먼지), 완성 순간 먼지가 펑 + 집이 통 튀어나옴. 개간은 덤불 → 돌 → 통나무가 진행도에 따라 하나씩 치워짐. 공사가 시작되면 광장 카메라가 현장을 비춘다.
- 공사 단계 그림: AI(GPT)로 그린 원본 `Tools/UIGen/stage_sources/` → `python Tools/UIGen/fit_stage_images.py`가 완성 집 그림과 같은 캔버스·위치로 맞춰 `Assets/Art/Settlement/Stage_<집>_0~3.png`를 만든다. 0단계(예정지)·1단계(골조)·2단계(벽)는 두 집이 같이 쓰고 3단계만 집마다. 0단계는 1단계 그림에서 골조만 걷어 낸 편집본이라 1단계와 같은 비율로 옮겨 돌 기초가 겹친다.
- 해달 이름·말·수치는 임시값. 표를 고치고 `Tools/Navigation/Build Global UI`를 다시 실행하면 에셋이 바뀐다.

## 3. 구조

```
데이터(SO)   SettlementConfig, BoardRequestDefinition, ConstructionDefinition,
             SettlementOtterDefinition, GuestbookEntryDefinition          Scripts/Settlement/Data
모델         Settlement(상태), SettlementRules(규칙), SettlementSaveData   Scripts/Settlement/Model
주인         SettlementManager (GlobalUI, 비용·시간·저장 요청)             Scripts/Settlement
화면         SettlementPresenter + 칩·안내 띠·게시판·건설·완료·진행 말풍선 Scripts/Settlement/UI
광장         SettlementPlazaView, DevelopmentGate, ConstructionSiteView,
             BuilderOtterController, GatherPointView, SettlementBoardPropView Scripts/Settlement/World
장소 잠금    ZoneDefinition._requiredDevelopment + ZoneAccess               Scripts/Navigation
만들기       SettlementSetup (데이터·화면·광장 배치), settlement_art.py(그림)
```

- **부탁 = 세계를 바꾸는 진행**, 퀘스트 = 행동 보상. 게시판 부탁은 퀘스트와 따로 간다.
- 광장 오브젝트는 지우지 않고 `DevelopmentGate`로 켜고 끈다 (집·벤치·가로등·울타리·피크닉·요정·막힌 길).
- 광장 해달은 이제 정착 진행이 내보낸다 (`PlazaSettings.otterCount = 0`). 재접속해도 같은 해달이 한 마리씩.
- 건설 해달 = 광부 해달 그림·걷기·곡괭이질을 그대로 쓰는 광장용 컨트롤러 (광산의 `MinerOtterController`는 그대로).
- 도감 등록 ≠ 주민. 정착 상태는 `SaveData.settlement`에만 있다.

## 4. 세이브

- `SaveData.settlement` (스키마 4): 단계, 끝낸 부탁, 열린 발전, 해달별 처지, 방명록 ID, 진행 중 건설, 나뭇가지 재생 시각, 한 번 보는 안내 표시.
- **옛 세이브(스키마 3 이하)는 모든 부탁을 끝낸 것으로 처리**한다 → 이미 쓰던 밭·낚시터가 다시 잠기지 않는다. 처음부터 P0를 보려면 세이브를 보관함으로 옮기고 시작 (메뉴 `OtterKingdom > Dev > Save Files` → 세이브 날리기, 나중에 되돌릴 수 있음).
