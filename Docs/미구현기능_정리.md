# 해달왕국 미구현 기능 정리 (낚시터 제외)

- 기준: `feature/Game_Structure` 브랜치, 커밋 `e0d106d`, 2026-09-28
- 비교 대상: `해달마을_클로드전달용_상세기획서.md`(원본), `해달왕국_클로드전달용_기획변경명세.md`(변경 명세)
- 두 문서가 충돌하면 변경 명세와 채팅에서 확정한 결정(모종 영구/소모 분리, 구역별 씬 분리, 밭 한 줄에 슬롯 3개)을 따랐다.
- 낚시터(수영·잠수 채집)는 이 문서에서 제외했다.
- 현재 구현된 기능은 `구현현황_정리.md`를 참고한다.

---

## 1. 구역 이동

| 항목 | 현재 상태 |
|---|---|
| 구역 이동 UI (화살표/표지판, "현재 위치: 밭" 표시) | 없음 |
| 씬 전환 코드 (`SceneManager.LoadScene`) | 없음 |
| 빌드 설정에 Farm·Plaza 씬 등록 | 안 됨 (`SampleScene`만 등록) |
| 다른 구역에 있는 동안 생산 유지 | 안 됨 |

**주의할 점**
- `GameManager`가 Farm 씬에만 있고 `DontDestroyOnLoad`가 아니다. 광장으로 이동하면 밭 시간 진행과 자동 저장이 멈춘다.
- 수확은 농부 해달의 애니메이션이 끝나야 일어나므로, Farm 씬이 열려 있지 않으면 수확이 되지 않는다.
- 원본 기획서 11.5는 "애니메이션이 보상을 직접 지급하지 않는다"고 정하고 있다. 씬 전환을 만들 때 생산 로직을 씬과 분리하는 작업을 함께 해야 한다.

## 2. 시설 확장과 해달 배치

| 항목 | 현재 상태 |
|---|---|
| 밭 개간 (잠긴 밭을 누르면 조건·가격 표시, 개간 구매) | 없음. 밭 2·3은 잠긴 이미지만 있고, 세이브에는 `plot_1`만 있음 |
| 해달 해금, 여러 마리 보유 | `OtterSaveData` 구조만 있고 로직 없음. 획득 방식은 기획에서도 미정 |
| 해달 배치·재배치 | 없음. `workerId`를 저장만 하고 쓰지 않아서, 해달을 배치하지 않아도 생산됨 |
| 생산 조건 검사 (해달 배치 + 모종 선택) | 없음 |
| 부족한 조건 표시 UI | 없음 |
| 세이브 로드 검증 (중복 ID, 존재하지 않는 작업자 ID, 한 해달의 중복 배치) | 없음 |

## 3. 밭

| 항목 | 현재 상태 |
|---|---|
| 작물 종류 | 당근만 있음. 양파·대파·토마토·딸기 등 없음 |
| 모종 보유/해금 목록 | 저장하지 않음. 작물 선택 팝업에 등록된 작물이 전부 나옴 |
| 마을 단계에 따른 작물 해금 | 없음 |
| 소모형 모종 재고 차감 | 없음 (`SeedType.Consumable` 값만 정의됨) |
| 요정 상인 NPC (정해진 날짜에 소모형 모종 판매) | 없음 |
| 첫 튜토리얼 10초 생산 | 없음 |
| 수확 연출 (아이콘이 가방으로 날아감, 획득 숫자, 효과음) | 없음 |

**원본 기획에서 바뀐 부분**
원본의 "6회분 저장소 / 자동 반복 생산 / 작물 전환 예약 / 가득 참(StorageFull)"은 지금의 "슬롯 3개 + 해달이 수확" 구조로 바뀌었다. 같은 역할을 할 규칙(예: 가방이 꽉 찼을 때 수확 처리)은 인벤토리 작업과 함께 다시 정해야 한다. `FarmBalanceData.storageCapacityCycles`는 정의만 있고 쓰이지 않는다.

**세이브 손상 문제**
본 파일과 백업이 둘 다 깨지면 안내 없이 새 게임을 시작하고, 다음 저장 때 손상된 파일을 덮어쓴다. 원본 기획서 11.4가 금지한 동작이다 ("조용히 새 게임으로 덮어쓰지 않는다").

## 10. 우선순위 제안

1. **씬 전환과 생산 유지 구조**: 이게 없으면 밭과 광장이 한 게임으로 이어지지 않는다.
2. **밭 개간 + 해달 해금·배치**: 변경 명세의 다음 검증 단계인 "두 번째 밭"에 필요하다.
3. **세이브 손상 시 덮어쓰기 방지**: 작은 수정이지만 테스터의 데이터가 날아갈 수 있다.
