# 재화 시스템 — 작업기록

작성일: 2026-09-23
문서 성격: 클로드와의 대화에서 진행한 작업 로그. 기획 확정 문서가 아니라 **다음 작업 재개 시 참고용 기록**이다.

## 1. 배경

OtterKingdom 프로젝트에 재화 시스템이 새로 추가되었다는 요청을 받고 구조를 먼저 둘러봤다. 확인해보니 재화를 다루는 코드가 두 갈래로 이원화되어 있었다.

- **기존 코인 로직**: `SaveData.coins` 필드를 `EconomyService`(순수 C# 클래스)가 감싸서 `GameManager`가 직접 사용 — `AddCoins`, `TrySpend`, `SellAll` 등 게임 로직에 딱 맞는 헬퍼 보유, 세이브(`SaveService`, JsonUtility 기반)에 자동으로 실림.
- **신규 재화 시스템**: `Currency`(ScriptableObject) + `CurrencyManager`(MonoBehaviour 싱글턴) + `CurrencyTransaction` 구조로 다중 화폐를 염두에 둔 설계. 전용 테스트 씬(`CurrencyTestScene`)에만 배선되어 있고, 세이브 연동·씬 배선·소비 검증이 전혀 없는 뼈대 상태.

즉 신규 시스템은 "멀티 화폐를 다룰 수 있는 뼈대"만 있고 저장/검증/씬 배선이 없어서, 그대로 `GameManager`에 갈아끼우면 저장이 깨지고 강화 로직 계약(잔액 부족 시 실패)이 깨지는 상태였다. 아래는 그 이원화 문제를 CurrencyManager 쪽으로 통합한 작업 내용이다.

## 2. 탐색 결과

`Assets/Scripts/Currency/` 하위 파일과 관련 에셋을 확인해서 나온 사실들.

- **CurrencyData.cs** — `Currency` ScriptableObject(ID, 표시명, 최대/최소 보유량)와 `CurrencyTransaction`(출처 구분자 `TransactionSource` 포함) 정의.
- **CurrencyManager.cs** — MonoBehaviour 싱글턴. `Dictionary<Currency,int>`로 지갑을 관리하고 `ProcessTransaction`으로 거래 처리 + `OnCurrencyChanged` 이벤트 방송.
- **CurrencyUI.cs / TestCurrencyUI.cs** — 특정 `Currency`를 구독해 카운트업 애니메이션으로 보여주는 UI, 테스트용 지급 버튼.
- 전용 테스트 씬 `CurrencyTestScene.unity`에만 `CurrencyManager`와 UI가 배선되어 있고, 메인 게임 흐름(`GameManager`)과는 연결되어 있지 않았다.
- `Assets/Scriptable Obejects/Gold.asset`에 이미 Gold `Currency` 에셋이 존재함을 발견 — `CurrencyID`가 문자열 `"1"`로 들어있지만 키로 그대로 쓸 수 있어 새 에셋을 만들 필요는 없었다.
- **인코딩 문제**: `CurrencyManager.cs`, `CurrencyUI.cs`, `TestCurrencyUI.cs` 3개 파일이 UTF-8이 아닌 CP949로 저장되어 한글 주석/로그 문자열이 깨져 있었다(`CurrencyData.cs`만 정상 UTF-8 BOM). `iconv -f CP949`로 원문을 복원해 의미를 확인한 뒤 UTF-8로 재저장했다.
- **버그**: `ProcessTransaction`이 `Mathf.Clamp(...)`의 반환값을 버려서 `MinCapacity`/`MaxCapacity`가 실제로 적용되지 않았고, 잔액 부족 검증이 없어 음수 거래 시 잔액이 무한정 내려갈 수 있었다.

## 3. GameManager 마이그레이션 내역

이원화된 두 시스템을 `CurrencyManager` 하나로 통합하면서 파일별로 바꾼 내용.

- **CurrencyData.cs** — `TransactionSource`에 `CropSale`(작물 판매 수입), `FarmUpgrade`(밭 강화 소비) 추가.
- **CurrencyManager.cs** — 인코딩 복구 + 다음 로직 보강:
  - `Instance`를 **lazy 싱글턴**으로 전환(최초 접근 시 자동으로 GameObject 생성) — 씬에 수동으로 배치하지 않아도 동작하게 함.
  - `ProcessTransaction`이 잔액이 한도를 벗어나면(예: 잔액 부족) 적용하지 않고 `false`를 반환하도록 수정(기존 Clamp 버그 제거).
  - `GetCurrency` 기본값을 `-1` → `0`으로 수정(빈 지갑은 0이 맞는 값).
  - `TrySpend`, `Add`, `LoadFromSave`, `SaveToSave` 편의 메서드 추가.
  - 생성을 유발하지 않는 순수 존재 확인용 `CurrencyManager.Exists` 프로퍼티 추가(4절 버그 수정 참고).
- **CurrencyUI.cs / TestCurrencyUI.cs** — 인코딩만 복구(로직 동일), 존재 확인 체크를 `Exists`로 교체(4절 참고).
- **SaveData.cs** — `coins` 필드 제거, `CurrencyBalance`(currencyId + amount) 클래스와 `currencies` 리스트 필드 추가.
- **FarmService.cs** — `TryUpgrade(EconomyService)` → `TryUpgrade(CurrencyManager, Currency)`로 시그니처 변경.
- **GameManager.cs** — `goldCurrency` 필드 추가, `economyService` 제거. `Awake`에서 `CurrencyManager.Instance.LoadFromSave(...)`로 저장 복원, `SaveNow`에서 `SaveToSave(...)`로 지갑을 저장. 전체 판매/강화 버튼 UI 로직도 CurrencyManager 기반으로 교체(`SellAllForGold` 헬퍼 신설, `lifetimeSales` 집계는 그대로 보존).
- `EconomyService.cs`(+meta), `Economy.meta` 삭제 — 더 이상 참조하는 곳이 없어진 데드 코드.
- **Farm.unity** — `GameManager` 컴포넌트에 기존 `Gold.asset`을 `goldCurrency`로 연결(YAML 직접 편집, 새 GameObject는 만들지 않음 — lazy 싱글턴이 대신 처리).

## 4. 추가 기능

마이그레이션 이후 사용성 요청으로 두 가지를 더 붙였다.

- **재배 시간 단축**: 씬에 실제 `CropDefinition` 에셋이 없어 `GameManager.EnsureDefaultData()`의 런타임 기본 당근이 쓰이고 있었고, `baseDurationSec`가 60초라 1사이클 60초 × 저장 용량 6사이클(`FarmBalanceData` 기본값) = 총 6분이 걸렸다. 10초로 줄여 총 60초면 저장이 꽉 차도록 조정.
- **화면 상단 재화 HUD** — `CurrencyHud.cs` 신설. 씬에 아무 것도 배치하지 않아도 **실행하는 순간 코드로** Canvas/패널/텍스트를 직접 생성해 화면 상단 중앙에 "코인 N" 형태로 띄운다. `CurrencyManager.OnCurrencyChanged` 이벤트를 구독해 판매·강화 등으로 잔액이 바뀌면 실시간으로 갱신되고, 별도 폰트 에셋 없이 Unity 내장 폰트(`LegacyRuntime.ttf`)를 쓴다.
- `GameManager.Awake()`에서 `CurrencyManager.Instance.LoadFromSave(...)` 직후에 `CurrencyHud.Show(goldCurrency)`를 호출해 연결했다.

## 5. 버그 수정: "Some objects were not cleaned up" 경고

Play를 멈추면 에디터가 `CurrencyManager` 오브젝트가 정리되지 않았다고 경고했다.

**원인**: `CurrencyManager.Instance`를 lazy 싱글턴으로 바꾸면서, `Instance`를 읽는 행위 자체가 "없으면 새로 만들어라"가 되어버렸다. 그런데 `CurrencyUI.OnDisable()`과 `CurrencyHud.OnDestroy()`에 남아있던 `if (CurrencyManager.Instance != null)` 가드가 원래는 "매니저가 있으면"을 확인하려는 널 체크였는데, 이제는 그 체크 자체가 생성을 트리거하게 된 것.

Play를 멈추어 씬이 닫히는 도중에 `CurrencyHud`가 파괴되면서 `OnDestroy()`가 호출되고, 그 안에서 `CurrencyManager.Instance`를 체크하다가 **씬이 닫히는 도중에 새 `CurrencyManager` GameObject를 하나 더 생성**해버렸다. 이 신생 오브젝트는 생성되자마자 씬이 닫혀버려서 정리되지 못하고, 에디터가 경고한 것이다. 경고 문구의 "Did you spawn new GameObjects from OnDestroy?"가 원인을 정확히 짚어줌.

**해결**: 생성을 유발하지 않는 순수 존재 확인용 프로퍼티 `CurrencyManager.Exists`(`_instance != null`)를 추가하고, `CurrencyUI.Start()/OnDisable()`와 `CurrencyHud.OnDestroy()`의 보호 체크를 모두 `Instance != null` 대신 `Exists`로 교체했다. "사용하려고 부르는" 호출(`CurrencyManager.Instance.GetCurrency(...)` 등)은 그대로 유지해서 평소에는 lazy 생성이 정상 동작하도록 했다.

## 6. 다음 확인 사항

Unity 에디터를 직접 실행할 수 없어 아래는 직접 검증이 필요하다.

- [ ] `Farm.unity` Play → 밭고랑 클릭 → 디버그 패널에서 코인 표시·전체 판매·강화가 CurrencyManager 기반으로 정상 동작하는지
- [ ] 화면 상단 `CurrencyHud`가 뜨고, 판매/강화 시 실시간으로 숫자가 바뀌는지
- [ ] 재배 사이클이 체감상 빠르다고 느껴지는지(10초 기준이 적당한지)
- [ ] Play 종료 → 재시작 시 `save.json`에 저장된 코인이 제대로 복원되는지
- [ ] Play를 멈췄을 때 "Some objects were not cleaned up" 경고가 더 이상 뜨지 않는지
- [ ] `CurrencyTestScene.unity`도 열어 기존 테스트 UI(입력 후 지급)가 인코딩 수정 이후에도 그대로 동작하는지
