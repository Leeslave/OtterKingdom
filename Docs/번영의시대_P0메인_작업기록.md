# TASK-000007 — B 담당 P0 메인 연결

기준일: 2026-11-06. 이번 범위는 Lv.23~27 메인 25개와 기존 진행 보존이다. 정식 프롤로그 및 P1/P2 콘텐츠는 포함하지 않는다.

## 반영

- `ProsperityQuestPlan`에 레벨당 5개, 총 25개를 정의했다. 원본 135개 통합기획서가 현재 폴더에 없어, 개발분담·B 착수규칙·실제 구현된 7개 연구 및 주문 2개를 기준으로 구성한 P0 표다. 목표 수량은 플레이 실측 전 임시값이다.
- 게임 로드 시 QuestDatabase를 메모리에서 복제하고 새 메인을 추가한다. 기존 퀘스트 284개 데이터, 기존 108개 후기 메인 ID, 씬·프리팹·폰트·레벨표는 변경하지 않는다. 에디터 생성 메뉴를 실행할 필요가 없다.
- 새 ID는 `prosperity_main_{level}_{step}`이다. 기존 enum 뒤에 ProsperityRecord를 추가하고 연구·주문 완료, 실제 창고 재고, 수레 배정에서 진행을 확인한다. 선행 연구·첫 제작·사업·주택 개량·장터 주문은 앞서 완료했어도 인정한다.
- 새 메인은 선행 보상을 순서대로 받아야 열린다. 기존 메인의 모으기 건너뛰기 규칙을 새 체인에는 적용하지 않는다.
- 레벨당 XP는 현재 LevelTable.ExpToNext의 1/5씩 정수 배분하고 마지막에 나머지를 더한다. 골드는 해당 레벨의 기존 메인 골드 합을 같은 방식으로 배분한다. XP 곡선·조개·총 골드 예산은 유지한다.

## P0 표

| Lv | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| 23 | I02 연구 | 첫 석재 블록 | 번영 계획 완료 | E01 연구 | 당근 주문 완료 |
| 24 | L02 연구 | 수레 경로 켜기 | 첫 판재 | 창고 판재 6개 | 목재 주문 완료 |
| 25 | C01 연구 | C02 연구 | 첫 주택 개량 | 표지판/가로등 제작 | 작물 수확 30개 |
| 26 | L01 연구 | 초도 주문 2개 완료 | 작물 수확 60개 | 물고기 10마리 | 판매 1,000골드 |
| 27 | 초기 연구 7개 완료 | 창고 판재 12개 | 창고 석재 블록 6개 | 가구 2개 배치 | 일일 보상 1개 |

창고 목표는 제작 누계가 아닌 현재 재고다. 목표가 열린 동안 필요 수량에 도달하면 완료 진행을 보존한다. 수확·낚시·판매·가구는 기존 이벤트/초과 진행 규칙을 사용한다. 수레 목표는 배정된 경로를 확인한다.

## 기존 세이브 전환

부분 진행을 다른 행동의 진행량으로 환산하거나, 이미 지급한 보상을 다시 주지 않는다. 원본 대응표가 없는 상태에서 기존 진행을 지우지 않도록 다음 경계를 사용한다.

| 기존 상태 | 선택 |
|---|---|
| Lv.23 미만 | Lv.23부터 새 메인 |
| Lv.23~27, 현재/이후 레벨의 옛 메인에 진행·수령 기록 없음 | 현재 레벨부터 새 메인 |
| 옛 메인에 양수 진행, 미수령 완료 또는 수령 기록이 있음 | 기록이 있는 마지막 레벨까지 옛 메인을 유지하고 다음 레벨부터 새 메인 |
| Lv.27 옛 메인이 진행 중 | 이번 P0 전환 보류, 기존 체인 유지 |
| 처음 적용하는 Lv.28 이상 세이브 | 기존 체인 유지 |
| 이미 새 체인을 시작한 뒤 Lv.28 도달/재접속 | 저장된 선택 유지, 새 Lv.27 마지막 보상 이후 기존 Lv.28 첫 메인으로 연결 |

선택은 퀘스트 저장 목록의 `__prosperity_main_start_v1`에 한 번 저장한다(23~27: 시작 레벨, 0: 기존 체인 유지). 기존 기록, 모르는 퀘스트 ID, 초과 진행, 일일 날짜는 그대로 남는다. 과거 XP·골드·RP·가방·산업 데이터를 직접 보정하지 않는다. 기존 schema 6에 선택 기록을 추가하며 저장 구조와 버전은 유지한다.

전환 시작 레벨의 첫 새 메인은 직전 레벨의 옛 마지막 메인을 기다린다. 이후 레벨은 새 체인을 따라간다. 예: 기존 Lv.23 수확 317개 진행은 그대로 보존하고, 옛 Lv.23 판매까지 끝낸 뒤 새 Lv.24 1단계로 진입한다. 기존 유저 모두를 즉시 새 메인으로 바꾸는 전체 135개 전환은 P1/P2 및 원본 대응표가 준비될 때 별도로 진행한다.

## 검증

- 설치된 Unity 참조를 사용한 런타임·에디터·전체 테스트 소스 컴파일 통과(오류 0).
- .NET 연구·RP·장터·온보딩·저장·P0 표/전환 규칙 검사 **67개 통과, 실패 0**. 이번 순수 규칙 테스트 12개 포함. XP/골드 정수 배분, 부분 진행·미수령·수령·고레벨 보존, 저장 왕복, 실제 연구/주문 ID를 검사한다.
- Unity 전용 통합 테스트 6개 추가 및 컴파일 확인. DB 원본 보존·25개 생성·레벨별 예산·진행 중 레벨 경계·순차 열림·중복 수령·Lv.28 연결·보유량 변화를 검사한다. **Unity 실행은 미실행**이므로 이 6개가 통과했다고 주장하지 않는다.
- 콘텐츠·웹 저장 모의 검사는 기존 검사 도구로 별도 실행한다. 이 검사는 런타임 새 메인의 Unity UI를 검증하는 것이 아니다.
- 검증 임시 빌드는 `tmp/task7-verify/`를 사용했다. 기존 `tmp/RuntimeCheck.csproj` 등은 덮어쓰지 않았다. NuGet 소스가 없는 로컬 설정으로 외부 패키지를 받지 않았다.

## 캡처와 남은 검증

남은 검증: Unity 통합 테스트 실행, 새/전환 세이브로 실제 Lv.23~28 순차 진행·저장 재접속·UI, Android/Web 빌드 및 실기기 입력, 수량과 체감 시간. 정식 프롤로그·기록관 다시 보기와 B P1/P2 작업은 여전히 남는다.
