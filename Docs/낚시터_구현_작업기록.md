# 낚시터 구현 작업기록 (2026-09-28)

## 결정 사항
- 변경명세서의 "초기 낚시터 = 수영·잠수 채집"은 **폐기**하고 낚싯대 낚시로 구현. 이미지와 정확히 맞추기 어렵다는 판단.
- 흐름: 선착장 끝 점선 원 탭 → "낚시를 진행하시겠습니까?" → 예 → 낚시 해달이 원으로 이동 → 이후 **자동 반복**.
  - 해달 탭 → "낚시를 중단하시겠습니까?" → 예를 누를 때까지 계속 낚시함.
  - 중단 시 낚는 중이던 것(입질~끌어올리기)은 버려짐. 끌어올리기가 끝난 시점에 인벤토리에 들어가므로, 기뻐하기/시무룩 중에 중단하면 이미 얻은 것으로 처리됨.
- 캐스팅 후 10~30초 뒤 입질. 물고기 50% / 쓰레기 50%.
- 낚싯대 강화: Lv.1 50%, 레벨당 +5%p, 최대 Lv.5(70%). 비용 100/200/400/800 코인.
- 아이템: 물고기(`fish_basic`, 20코인), 쓰레기(`trash_basic`, 1코인). 기존 판매 UI에 같이 나옴.
- 낚시터는 단독 씬 `Fishing.unity`. 저장 데이터만 공유하고, 씬 이동 로직은 밭·광장·낚시터가 어느 정도 완성된 뒤 작성.

## 사용자가 할 일
1. Unity에서 `OtterKingdom > Tools > Setup Fishing Scene` 실행 → 스프라이트 슬라이스, `Assets/Prefabs/Fishing/FishingOtter.prefab`, `Assets/Data/Fishing/FishingBalanceData.asset`, `Assets/Scenes/Fishing.unity` 생성.
2. (선택) Farm.unity의 GameManager `Fishing Balance` 칸에 `FishingBalanceData.asset` 연결. 비워두면 코드 기본값(위 수치와 동일)을 쓰지만, 에셋에서 가격을 바꾸면 밭 씬 판매 UI에는 반영되지 않음.

## 구조
| 파일 | 역할 |
|---|---|
| `Scripts/Data/FishingBalanceData.cs` | 아이템 id/이름/가격, 입질 대기시간, 확률, 강화 비용 (SO) |
| `Scripts/Fishing/FishingService.cs` | 낚싯대 레벨/강화, 물고기·쓰레기 판정, 입질 시간, 낚시 중 여부 (plain C#) |
| `Scripts/Inventory/SellableItem.cs` | 판매 UI 한 줄 (작물 + 낚시 아이템 공용) |
| `Scripts/View/FishingOtterController.cs` | 배회(Idle↔Walk) + 낚시 상태머신 |
| `Scripts/View/FishingSpotView.cs` | 점선 원. 탭하면 시작 팝업, 낚시 중엔 숨김. 낚싯대 강화 버튼 표시 |
| `Scripts/View/SpriteFrameAnimator.cs` | 코드 기반 스프라이트 애니메이션 (Animator 대신) |
| `Scripts/UI/GameUI.cs` | 기존 `FarmUI` 이름 변경. 확인 팝업, 낚싯대 강화 버튼/팝업, 판매 목록 일반화 추가 |
| `Editor/FishingSceneSetup.cs` | 씬/프리팹/에셋 생성 메뉴 |
| `Tools/SpriteRepack/repack_fishing_otter.py` | 원본 AI 시트 재패킹 |

- `GameManager`는 낚시 씬에도 하나 배치됨(작물·Gold·FishingBalance 동일하게 연결). 그래서 저장·코인·인벤토리·판매 UI를 공유하고, 낚시터에 있는 동안에도 밭 작물이 계속 자람(수확은 밭 씬의 농부 해달이 할 때만).
- 저장: `SaveData.rodLevel`(기본 1), `SaveData.fishingActive`. 낚시 중 상태로 저장되면 다음 진입 시 해달이 바로 낚시 자리에서 캐스팅부터 시작. 진행 중이던 한 번의 낚시는 저장하지 않음. 오프라인 낚시 보상도 없음.
- `FishingService.IsActive`가 유일한 기준. 원의 "예"와 해달의 "예"는 플래그만 바꾸고, 해달/원은 매 프레임 그 값을 따라감.
- 판매 버튼 문구 "작물 판매" → "판매", 목록 제목 "[보유 아이템]". `GameManager.SellCrop/GetCropQuantity` → `SellItem/GetItemQuantity`. 디버그 "전체 판매"도 낚시 아이템 가격을 반영하도록 수정. `TransactionSource`에 `FishingSale`, `RodUpgrade` 추가.

## 낚시 흐름 / 애니메이션
```
[배회] Idle(2~5초) ⇄ Walk(선착장 다각형 안 랜덤 목적지, A*)
[낚시] GoToSpot → Cast(0~2) → Wait(2~7 반복, 10~30초) → Bite → Pull → 물고기면 CatchFish / 쓰레기면 CatchTrash → Cast …
```
| 클립 | 시트(원본 이미지) | 프레임 | fps | 반복 |
|---|---|---|---|---|
| Idle | Cast(6번) | 0 | - | ○ |
| WalkRight/Left/Down/Up | Walk(7번) 행 0/1/2/3 | 0~7 | 10 | ○ |
| Cast | Cast | 0~2 | 5 | × |
| Wait | Cast | 2~7 | 4 | ○ |
| Bite | Bite(2번) | 0~7 | 8 | × |
| Pull | Pull(4번) | 0~7 | 8 | × |
| CatchFish | CatchFish(5번) | 0~7 | 5 | × |
| CatchTrash | CatchTrash(3번) | 0~7 | 5 | × |

- fps/반복 여부는 프리팹의 SpriteFrameAnimator에서 조절 가능(셋업 메뉴를 다시 실행하면 위 값으로 덮어씀).
- 멈춰 있을 때는 Idle(오른쪽을 보는 측면)을 쓰고, 왼쪽으로 걷다 멈추면 flipX로 방향을 유지. 걷기는 4방향 행을 그대로 사용(flip 없음).
- 스프라이트 시트에는 앉은 자세가 없어서 서서 낚시함.

## 스프라이트 재패킹
농부 해달과 같은 방식(알파 연결 성분으로 프레임 추출 → 크기 통일 → 발 기준선·모자 중심 정렬). 다른 점:
- 모자 색이 올리브(≈168,160,127)라서 모자 검출 색 범위를 바꿈.
- 2×4 시트는 한 줄 8프레임으로 재배치. 걷기 시트는 프레임끼리 붙어 있는 곳이 있어서, 다른 프레임보다 1.6배 이상 큰 덩어리는 가장 빈 세로줄에서 자름.
- 스케일은 "모자 위 → 발" 높이만 사용. 모자 폭까지 섞으면 옆모습 걷기의 챙이 좁게 측정돼서 걷는 해달이 약 9% 커졌음.
- Bite(웅크림), Pull(뒤로 젖힘)은 서 있는 기준 포즈가 없어서 Cast의 스케일을 그대로 씀(같은 원본 해상도).
- 결과: 셀 428×276, 발 기준선은 셀 위에서 258px. 피벗을 발 위치(0.5, 18/276)에 두어서 transform 위치 = 발 위치. PPU 145 → 서 있는 키 약 1.52 유닛.
- 원본을 다시 받으면: `python Tools/SpriteRepack/repack_fishing_otter.py <원본폴더(2~7.png)> <출력폴더>` 실행 후 `Assets/Sprites/Characters/FishingOtter/`에 덮어쓰기. 셀 크기가 바뀌면 `FishingSceneSetup.cs`의 `CellW/CellH/BaselineFromTop`도 수정.

## 씬 배치 (배경 픽셀 기준, 원점 왼쪽 위)
- 배경 1024×1536, PPU 96 → 16유닛 높이 = 카메라 ortho 8(밭 씬과 동일). 9:16 화면에서 좌우 약 80px씩 잘림.
- 낚시 자리: (665, 655). 찌(발에서 오른쪽으로 약 1유닛)가 선착장 끝 너머 물 위에 오도록 맞춤.
- 이동 영역: (85,590)~(690,695) 사각형(선착장 상판 + 왼쪽 모래), clearance 0.25. 광장의 `PlazaWalkableArea`/`PlazaAreaPolygon`을 그대로 재사용. 넓히려면 Scene 뷰에서 `WalkableArea/Dock` 다각형을 편집하면 되지만, 셋업 메뉴를 다시 돌리면 초기화되므로 확정되면 `WalkablePx` 상수로 옮길 것.
- 정렬 순서: 배경 0 / 점선 원 1 / 해달 2.

## 미확인 / 남은 일
- Unity 에디터가 열려 있어서 에디터 안에서 실행하거나 플레이 테스트는 못 했음(생성된 csproj로 dotnet 빌드만 통과 확인). 셋업 메뉴 실행과 플레이 확인이 필요.
- 낚시 결과 표시(예: "+물고기" 떠오르는 텍스트)는 없음. 인벤토리/판매 UI에서만 확인 가능.
- 씬 이동, 여러 낚시 해달/자리 확장, 오프라인 낚시 보상은 아직 없음.
