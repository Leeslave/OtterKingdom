# 방문객 해달 애니메이션 · 타이틀 씬 — 작업기록

작성일: 2026-09-30
문서 성격: 클로드와의 대화에서 진행한 작업 로그. 기획 확정 문서가 아니라 **다음 작업 재개 시 참고용 기록**이다.

이번 세션에서 한 일은 두 가지다.

1. GPT가 만들어 준 방문객 해달 3종(먹보·잠꾸러기·화가) 애니메이션 팩을 프로젝트 규약에 맞게 다시 만들어 광장에 넣었다.
2. 타이틀 씬을 만들었다. 화면을 누르면 광장으로 넘어간다.

두 작업 모두 **유니티 에디터가 켜져 있어서 배치 모드로 실행하지 못했다.** 코드는 Unity 6000.3.8f1의 DLL로 컴파일 검사까지만 했다(런타임·에디터 스크립트 전체, 오류 0). 아래 "실행 방법"의 메뉴를 한 번씩 눌러야 실제 에셋이 만들어진다.

---

## 1. 방문객 해달 애니메이션 (광장)

### 1-1. 받은 팩 검토 결과 — 그대로는 못 씀

GPT 팩(`OtterVisitors_Unity_Pack`)은 시트 3장(각 1024×1536, 4열×6행 = 24프레임)과 빌드 스크립트 `BuildOtterVisitors.cs`로 되어 있다. 그림은 쓸 만하지만 스크립트를 그대로 넣으면 광장에서 제대로 동작하지 않는다.

| 문제 | 팩의 방식 | 우리 프로젝트 규약 |
|---|---|---|
| Animator 파라미터 | `State` 정수 하나 (0~6) | `IsMoving`(bool), `WalkDir`(int 0 옆/1 아래/2 위), `WalkAnimSpeed`, 동작 트리거 (`OtterVisualController`) |
| 왼쪽 걷기 | WalkLeft 클립 따로 (m_FlipX 키) | 스크립트가 `spriteRenderer.flipX`로 뒤집음 |
| 슬라이스 | 프레임마다 다른 사각형 + 프레임별 피벗 | 오프라인에서 균일 격자로 재정렬 후 격자 그대로 자름 (`Tools/SpriteRepack`) |
| 결과물 위치 | 실행할 때마다 `Built`, `Built 1`… 새 폴더 | 정해진 경로에 덮어쓰기, 프리팹은 제자리 갱신 |
| 광장 연결 | 없음 | `PlazaSettings.otterPrefabs`에 등록돼야 스폰됨 |

프레임별 피벗 방식은 팩 README에도 적혀 있듯 프레임마다 몸이 흔들린다. 그래서 팩의 스크립트는 쓰지 않았고, 시트 원본만 가져와 재정렬했다. 팩은 프로젝트에 복사하지 않았다.

시트 상태는 확인했다. 세 장 모두 알파가 실제로 있고, 캐릭터마다 큰 알파 덩어리가 정확히 24개다. 나머지는 1~3px짜리 잡티뿐이다.

### 1-2. 시트 재정렬 — `Tools/SpriteRepack/repack_otter_visitors.py`

기존 `repack_farmer_otter.py`, `repack_miner_otter.py`와 같은 방식이다.

- 알파 덩어리 24개를 찾아 행·열 순서로 정렬한다.
- 모든 프레임을 **240×260 칸**에 넣는다. 세 캐릭터 공통 크기다.
  - 발끝은 칸 위에서 249px 되는 선에 맞춘다.
  - 몸 중심은 칸의 가운데 세로선에 맞춘다.
- 몸 중심 기준은 **몸통 띠(높이 45~65% 구간)의 x 중앙값**이다.
  - 농부 스크립트처럼 모자 색으로 찾지 않은 이유: 먹보는 모자가 없고, 잠꾸러기는 수면모자 꼬리가 좌우로 삐친다.
- 배율은 바꾸지 않았다. 생성 과정에서 생긴 프레임별 크기 차이는 그대로 남아 있다.
- 결과: `Assets/Sprites/Characters/Visitors/{Snack,Sleepy,Painter}.png`, 각 960×1560.
- 사용법: `python repack_otter_visitors.py <원본 폴더> <출력 폴더>`. 원본 폴더에 Snack.png, Sleepy.png, Painter.png가 있어야 한다. 출력에 `layout.json`(칸 크기, 발끝 위치, 캐릭터별 대기 키)도 나온다.
- 미리보기로 확인한 결과, 발끝선과 중심선이 맞고 옆 프레임 그림이 섞여 들어오지 않았다.

시트 행 구성 (원본과 같음):

| 행 | 내용 | 먹보 Snack | 잠꾸러기 Sleepy | 화가 Painter |
|---|---|---|---|---|
| 0 | 대기 (정면, 1·3열은 눈 감음) | | | |
| 1 | 앞으로 걷기 (Walk_Down) | | | |
| 2 | 뒤로 걷기 (Walk_Up) | | | |
| 3 | 옆으로 걷기 (오른쪽 보기) | | | |
| 4 | 고유 동작 A | Eat (빵 먹기) | Yawn (하품) | Paint (그리기) |
| 5 | 고유 동작 B | Happy (기뻐하기) | Sleep (앉아서 졸기) | Wave (인사) |

### 1-3. 세팅 도구 — `Assets/Editor/OtterVisitorSpriteSetup.cs`

메뉴: **OtterKingdom > Tools > Setup Otter Visitor Animations**

`FarmerOtterSpriteSetup`와 같은 구조다.

- **스프라이트**
  - 240×260 격자, 가운데 피벗으로 자른다.
  - PPU는 132다. 방문객 키가 약 220px라서, 농부 해달과 같은 약 1.67유닛(`PlazaSettings.otterHeight`)이 되게 맞춘 값이다.
- **클립**: `Assets/Animations/Visitors/{이름}/{이름}_{클립}.anim`
  - 대기: 프레임 순서 `0,0,0,1,2,2,2,3`, 3fps. 눈 깜빡임 프레임을 잠깐씩만 보이게 했다.
  - 걷기 3방향: 6fps.
  - 고유 동작: 아래 표.
  - 모든 클립 끝에 마지막 프레임 키를 한 번 더 넣었다. 마지막 프레임도 1/fps만큼 보이게 하기 위해서다. 농부 쪽 클립은 이게 없어서 마지막 프레임이 거의 안 보인다.
- **컨트롤러**: 농부 컨트롤러에서 Harvest만 뺀 구조다.
  - Idle ↔ Walk / Walk_Down / Walk_Up 전환은 `IsMoving`, `WalkDir`로 한다.
  - 고유 동작은 Any State → 트리거로 들어가고, 정해진 횟수만큼 재생한 뒤(exit time) Idle로 돌아온다.
  - 속도 파라미터 `WalkAnimSpeed`, `IdleActionAnimSpeed`가 있다.
- **프리팹**: `Assets/Prefabs/Plaza/PlazaOtter_{Snack,Sleepy,Painter}.prefab`
  - 구조는 `PlazaOtter`와 같다. 루트에 SortingGroup, OtterWanderAgent, OtterVisualController가 있고, `Visual` 자식에 SpriteRenderer와 Animator가 있다.
  - `Visual`은 (249 − 130) / 132 유닛만큼 올려서 루트가 발끝에 오게 했다.
  - 이미 있으면 제자리에서 갱신한다. 인스펙터에서 바꾼 값은 유지된다.
- **광장 등록**: `Assets/Data/Plaza/PlazaSettings.asset`의 `otterPrefabs`에 세 프리팹을 추가한다. 이미 들어 있으면 넣지 않는다.
- 다시 실행해도 안전하다. 클립과 컨트롤러 폴더는 지우고 새로 만든다.

고유 동작 설정:

| 캐릭터 | 트리거 | fps | 반복 후 Idle | 비고 |
|---|---|---|---|---|
| Snack | Eat | 4 | 2회 | |
| Snack | Happy | 4 | 2회 | |
| Sleepy | Yawn | 3 | 1회 | |
| Sleepy | Sleep | 2 | 3회 | |
| Painter | Paint | 4 | 2회 | |
| Painter | Wave | 4 | 2회 | 순서 `2,0,1,0`. 3열은 들어 올린 손이 바뀌어 반복하면 튀어서 뺐다 (팩과 같은 판단) |

### 1-4. `OtterVisualController` 수정

`PlayTriggerNames`에 `Happy, Yawn, Sleep, Paint, Wave`를 추가했다. `Eat`은 원래 있었다. 컨트롤러에 있는 트리거만 쓰기 때문에 농부 해달 동작은 달라지지 않는다.

### 1-5. 알아둘 점 / 남은 일

- **고유 동작은 장난감 옆에서 놀 때(`OtterWanderAgent.State.Play`)만 나온다.** 기존 광장 동작 방식이 그렇다. 평소 대기 중에도 랜덤으로 나오게 하려면 `OtterVisualController`를 따로 고쳐야 한다.
- 방문객의 대기 모습은 정면이다. 장난감 쪽을 보게 하는 flipX가 정면 그림에도 적용되지만, 거의 좌우 대칭이라 크게 어색하지 않을 것으로 본다. Play 모드에서 확인이 필요하다.
- **오프라인 방문 시스템(`OtterVisitBalanceData`)과는 연결되지 않았다.** 지금은 광장에 돌아다니는 캐릭터일 뿐이다. `placeholderOtterNames`의 "화가 해달"과 실제 캐릭터를 잇는 건 나중 일이다.
- 광장 스폰은 `otterCount = 5`마리를 프리팹 4종(농부 모습 + 방문객 3종)에서 랜덤으로 뽑는다.
- 그림 한계(생성물 특성): 걷기에서 다리 교차가 약하고, 프레임마다 얼굴·모자·몸 크기가 조금씩 다르다.

## 2. 타이틀 씬

### 2-1. 요구사항

- 모바일 세로 화면용 타이틀. 받은 그림 3장을 적용한다: 로고 간판, 해달 셋(농부·중앙·낚시), 마을 배경.
- 해달 아래 빈 곳에 "Touch To Start" 문구만 넣는다.
- 화면을 누르면 광장 씬으로 이동한다.

### 2-2. 그림

`Assets/Art/Title/`

| 파일 | 크기 | 비고 |
|---|---|---|
| `Title_Background.png` | 940×1672, RGB | 마을 배경 |
| `Title_Logo.png` | 941×1672, 투명 | 위쪽에 "해달 왕국" 간판 |
| `Title_Otters.png` | 941×1672, 투명 | 가운데에 해달 셋 (발끝이 그림 위에서 약 64%) |

세 장은 **같은 크기의 캔버스에 그려진 레이어**라서 겹쳐 놓기만 하면 위치가 맞는다. 그래서 잘라내지 않고 전체 크기로 썼다. 비율은 약 9:16이다.

### 2-3. 씬 구성 — `Assets/Editor/Navigation/TitleSceneSetup.cs`

메뉴: **OtterKingdom > Tools > Setup Title Scene**

`Assets/Scenes/Title.unity`를 새로 만들고, Build Settings의 **맨 앞(앱 시작 씬)**에 등록한다.

```
Main Camera               (단색 검정. Overlay 캔버스라 안 보이지만 "카메라 없음" 경고 방지용)
TitleCanvas               (Overlay, CanvasScaler 1080×1920 Expand — GlobalUI와 같게)
├─ Background             AspectRatioFitter EnvelopeParent → 화면을 꽉 채움, 남는 쪽은 잘림
├─ Foreground             AspectRatioFitter FitInParent → 잘리지 않게 화면 안에 맞춤
│  ├─ Otters              (Foreground 전체)
│  ├─ Logo                (Foreground 전체)
│  └─ TouchToStart        TMP, Cafe24Ssurround 76, 그림 아래에서 24% 높이
├─ TouchArea              투명 Image(raycast) + TitleScreen — 화면 어디든 누르면 시작
└─ ScreenFader            검은 막 + CanvasGroup + 기존 ScreenFader
EventSystem               InputSystemUIInputModule (타이틀엔 전역 UI가 없어서 따로 둠)
```

- 로고·해달·문구를 한 판(Foreground)에 모아서, 화면 비율이 달라도 셋의 위치 관계가 유지된다. 길쭉한 폰에서는 배경만 좌우가 잘리고 로고·해달은 온전히 보인다.
- 문구 색은 크림색(#FFF6E0)에 짙은 갈색(#4A2A12) 테두리를 넣어 로고 글자와 맞췄다.
  - 폰트 기본 머티리얼을 건드리지 않도록 `Assets/Art/Title/TouchToStart_Outline.mat` 복사본을 따로 만들어 쓴다.
- 합성 미리보기로 위치를 확인했다. 해달 발 아래 흙길 위에 문구가 온다.
- **다시 실행하면 씬을 통째로 새로 만든다.** 씬에서 직접 손본 내용은 사라진다.

### 2-4. 런타임 — `Assets/Scripts/Title/TitleScreen.cs`

- 문구 투명도를 코사인 파형으로 천천히 깜빡인다 (주기 1.6초, 최소 0.25).
- `IPointerClickHandler`로 화면 누름을 받는다 → `ScreenFader.FadeOut()` → `SceneManager.LoadScene("Plaza")`.
  - 넘어갈 씬 이름은 인스펙터의 `_nextScene`으로 바꿀 수 있다.
  - 두 번 눌러도 한 번만 진행된다.
  - 씬이 Build Settings에 없으면 에러 로그를 남기고 멈춘다.
- 광장 도착 후의 초기화(GameManager, 저장 불러오기, 전역 UI)는 기존 광장 씬 로직을 그대로 쓴다. 타이틀은 관여하지 않는다.

### 2-5. `GlobalUISetup.RegisterBuildScenes` 수정

원래는 Build Settings 목록을 "Plaza, Farm, Fishing, Mine, 나머지" 순으로 다시 짠다. 그래서 **Tools > Navigation > Build Global UI**를 다시 돌리면 타이틀이 첫 씬 자리를 잃는다. 이제 `Title.unity`가 있으면 항상 맨 앞에 넣도록 고쳤다.

## 3. 실행 방법 (에디터에서 한 번씩)

1. **OtterKingdom > Tools > Setup Otter Visitor Animations**
   → 방문객 클립·컨트롤러·프리팹을 만들고 PlazaSettings에 등록한다.
2. **OtterKingdom > Tools > Setup Title Scene**
   → Title.unity를 만들고 Build Settings 맨 앞에 등록한다.
3. Title 씬에서 Play → 화면 누름 → 광장에서 방문객 해달이 걷고, 장난감 앞에서 고유 동작을 하는지 확인한다.

Play 모드에서 확인할 것:

- 방문객 걷기 3방향과 좌우 뒤집기가 튀지 않는지
- 고유 동작 뒤에 Idle로 잘 돌아오는지
- 여러 화면 비율(Game 뷰 해상도 변경)에서 타이틀 로고·해달·문구가 잘리지 않는지
