# 광장 아트 교체 — 작업기록

작성일: 2026-09-28
문서 성격: 클로드와의 대화에서 진행한 작업 로그. 기획 확정 문서가 아니라 **다음 작업 재개 시 참고용 기록**이다.

## 1. 배경

광장 프로토(`e0d106d feat: 광장 프로토 구현`)의 배경·오브젝트 그림체가 해달 캐릭터와 선 느낌이 맞지 않아서, 사용자가 배경과 오브젝트를 새로 그려 전달했다. 전달받은 이미지는 3장.

1. **배치 이미지** — 새 배경 위에 새 오브젝트를 배치한 완성 예시(1024×1536, RGB). 이번 배치의 기준.
2. **오브젝트 시트** — 투명 배경 RGBA, 기존 시트와 같은 3열×4행 구성(Tree/House_Red/House_Blue, Bench/Fence_Rising/Fence_Falling, Lamp/Bush/Rock, Picnic/Log/Stump). 미리보기에서 보이는 어두운 배경은 실제로는 알파 0.
3. **배경** — 오브젝트 없는 바닥 그림(1024×1536, RGB). 기존 `Plaza_Ground.png`와 구도·해안선 위치가 거의 같다.

기존 파이프라인(슬라이스 스크립트 → `plaza_layout.json` → `PlazaSceneSetup` 메뉴)을 그대로 쓸 수 있는 구성이라 파일 교체 + 레이아웃 데이터 갱신으로 처리했다.

## 2. 아트 교체

- `Assets/Art/Plaza/Plaza_Ground.png` ← 새 배경. 해상도가 같아서 `walkable` 폴리곤, `spawnPoints`, `initialFocus`는 수정하지 않았다(미리보기상 해안선과 걷기 영역이 잘 맞음).
- `Tools/PlazaProps/plaza_props_sheet.png` ← 새 오브젝트 시트.
- `python Tools/PlazaProps/slice_plaza_props.py` 재실행 → `Assets/Art/Plaza/Props/Prop_*.png` 12장과 `plaza_props_pivots.json` 재생성. 스크립트 수정 없이 12개가 정상 분리됐다.
  - 실행하려면 `scipy`가 필요하다(이번에 로컬에 설치함).

새 오브젝트는 기존보다 픽셀 크기가 커졌다(예: Stump 190→265px 폭, Rock 297→338px). 기존 `scale`/`footprint` 값을 그대로 쓰면 전부 크게 나오고 충돌 영역이 어긋나서 아래처럼 갱신했다.

- **footprint** — 기존 좌표를 (새 폭/옛 폭, 새 높이/옛 높이) 비율로 재매핑. 그림 구도가 같아서 비율 변환으로 충분히 맞았다.
- **prop scale** — 배치 이미지에서 측정한 크기 기준으로 재설정(Tree 0.68, House_Red 0.70, House_Blue 0.60, Bench 0.455, Lamp 0.35, Fence 0.30, Bush 0.30, Rock 0.30, Picnic 0.51, Log 0.454, Stump 0.43).

## 3. 배치당 scale 기능 추가

배치 이미지에서는 같은 오브젝트가 서로 다른 크기로 쓰인다(가로등 대/소, 울타리 길이, 큰 덤불/작은 덤불, 큰 바위/작은 바위). 기존 레이아웃은 오브젝트 종류별 scale만 있어서, **placement마다 선택적 `scale` 배수**를 추가했다.

- `plaza_layout.json`의 placement에 `"scale": 0.83`처럼 넣는다. 생략하거나 0이면 1.
- `PlazaSceneSetup.cs` — `Placement.scale` 필드 추가. 인스턴스 `localScale`을 `(flipX ? -s : s, s, 1)`로 설정.
  - 스프라이트와 Footprint 폴리곤이 함께 스케일된다. `PlazaAreaPolygon`이 `transform.TransformPoint`로 월드 좌표를 구하기 때문에 런타임 코드 수정은 필요 없었다.
- `preview_layout.py` — 렌더링/footprint 계산에 `place.get('scale', 1)` 반영.

## 4. 배치 맞추기

`placements`를 배치 이미지 기준으로 전부 다시 작성했다(총 41개: 나무 1, 벤치 1, 집 2, 가로등 2, 울타리 14, 피크닉/통나무/그루터기 각 1, 덤불 15, 바위 3). 기존 배치와 달라진 주요 점: 파란 집이 위쪽, 빨간 집이 그 아래, 가로등 2개, 울타리 대폭 증가.

방법:

- **자동 맞춤** — OpenCV(`opencv-python-headless`, 로컬 설치) 템플릿 매칭으로 대략적인 추정 위치 주변 ±45px, 추정 scale의 0.7~1.3배, 좌우 반전 여부를 탐색해 오차가 가장 작은 값을 골랐다. 나무·집·벤치·가로등·피크닉·통나무·그루터기는 이 방식으로 정확히 맞았다.
- **수작업** — 덤불·울타리·바위는 배치 이미지 속 그림이 시트와 조금 달라서(꽃 개수, 기둥 개수 등) 매칭이 작은 scale 쪽으로 쏠렸다. 그래서 배치 이미지 격자를 보고 직접 좌표/크기를 넣었다. **이 부분은 배치 이미지와 약간 다를 수 있다.**
- 빨간 집 왼쪽 울타리(785, 322)는 집에 거의 가려진다. 필요 없으면 지워도 된다.

검증: `preview_layout.py`로 렌더링해 배치 이미지와 나란히 비교, 기본 오버레이(footprint·걷기 영역 표시)로 충돌 영역 위치도 확인했다.

## 6. 남은 일 / 미확인

- **Unity에서 `OtterKingdom > Tools > Setup Plaza Scene` 실행 필요.** 실행해야 오브젝트 프리팹(스프라이트 PPU·pivot·Footprint)과 `Assets/Scenes/Plaza.unity`가 새 데이터로 다시 만들어진다. 그 전까지 커밋된 씬/프리팹은 옛 값 기준이다.
- Unity 안에서는 아직 확인하지 않았다. 확인할 것: 해달이 오브젝트 뒤/앞으로 자연스럽게 정렬되는지, 울타리·덤불 footprint 때문에 길이 막힌 곳이 없는지, 스폰 지점이 막힌 영역 안에 들어가지 않았는지.
- 덤불·울타리·바위 위치는 미리보기를 보며 `plaza_layout.json`에서 미세 조정하면 된다(`python Tools/PlazaProps/preview_layout.py out.png` → 오버레이 확인).
