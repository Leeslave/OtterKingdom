## 0. 요약 (Claude가 먼저 읽을 것)

게임은 아직 `InventoryService`(itemId → 수량 목록)를 쓰고 있다. `feature/Inventory`의 `Inventory`(용량, 확장, 이벤트, UI 포함)로 바꿀 때 필요한 부품은 **인벤토리 쪽에 이미 다 있다.** 교체 작업은 `GameManager`만 고치면 되고, 인벤토리/재화 폴더는 수정하지 않는다.

1. 세이브 불러오기/저장: `InventoryManager.LoadFromSave` / `WriteToSave` (형식은 지금과 같은 `List<ItemStack>`)
2. 판매: `InventoryManager.TrySell` / `SellAll` (판매가는 `ItemDefinition.SellPrice`)
3. 수확 전 가방 확인: `Inventory.GetAddableAmount`
4. `SaveData`에 `inventoryCapacity` 필드 하나 추가

**결정 필요 2개**는 5장에 있다 (아이템 ID, 씨앗).

## 1. 인벤토리 쪽 API

| 용도 | API | 비고 |
|---|---|---|
| 가방 | `InventoryManager.Instance.Inventory` | 씬에 `InventoryManager` 배치 필요 (`DontDestroyOnLoad`, `DefaultExecutionOrder(-100)`) |
| 넣기 | `Inventory.Add(item, amount, ItemChangeReason.Harvest)` | 실제로 넣은 개수 반환 (칸/최대 스택에 걸리면 적을 수 있음) |
| 빼기 | `Inventory.TryRemove(item, amount, reason)` | 부족하면 false, 아무것도 안 바뀜 |
| 개수 | `Inventory.GetCount(item)` | |
| 넣을 수 있는 개수 | `Inventory.GetAddableAmount(item)` | 새 종류인데 빈 칸이 없으면 0 |
| 변경 알림 | `Inventory.OnItemChanged` | `ItemChangedEvent(Item, OldCount, NewCount, Reason)` |
| 판매 | `InventoryManager.TrySell(item, amount)` | 아이템 차감 후 골드 지급 (`TransactionSource.ItemSale`) |
| 전체 판매 | `InventoryManager.SellAll(filter)` | 예: `SellAll(i => i.Category == 작물)`. 받은 금액 합계 반환 |
| 불러오기 | `InventoryManager.LoadFromSave(save.inventory, save.inventoryCapacity)` | 게임 시작 시 한 번, 빈 가방에서 |
| 저장 | `InventoryManager.WriteToSave(save.inventory)` | 기존 목록을 지우고 다시 씀 |
| ID → 아이템 | `InventoryConfig.ItemDatabase.TryGet(itemId, out item)` | |

- 아이템은 문자열 ID가 아니라 `ItemDefinition`(ScriptableObject)으로 다룬다. 이름, 설명, 아이콘, 판매가, 카테고리, 희귀도가 들어 있다.
- 세이브에는 지금처럼 `ItemStack(itemId, quantity)`로 저장된다. **`SaveData.inventory` 형식은 바뀌지 않는다.**

## 2. `GameManager` 교체 예시

```csharp
// Awake: 불러오기 (LoadGoldFromSave 옆)
InventoryManager.Instance.LoadFromSave(save.inventory, save.inventoryCapacity);

// SaveNow: 저장 (WriteGoldToSave 옆)
InventoryManager.Instance.WriteToSave(save.inventory);
save.inventoryCapacity = InventoryManager.Instance.Inventory.Capacity;

// HarvestSlot: 가방에 자리가 있을 때만 수확 (7.3 (2))
var item = LookupItem(crop.cropId);            // ItemDatabase.TryGet
if (InventoryManager.Instance.Inventory.GetAddableAmount(item) < crop.yieldCount)
    return;                                    // 슬롯은 AwaitingHarvest로 남음
var harvested = farmService.Harvest(plotIndex, slotIndex);
foreach (var stack in harvested)
    InventoryManager.Instance.Inventory.Add(LookupItem(stack.itemId), stack.quantity, ItemChangeReason.Harvest);

// SellAllForGold / SellItem
InventoryManager.Instance.SellAll();           // 또는 TrySell(item, quantity)
```

- `InventoryService`, `SellableItem`, `SaveData.inventory`를 직접 고치는 코드는 교체 후 지운다.
- `ItemDatabase`에 없는 ID가 세이브에 있으면 **버리지 않고 보관했다가 저장할 때 그대로 다시 쓴다** (경고 로그만 남김). ID를 바꾸거나 아이템을 지워도 데이터가 사라지지 않는다.

## 4. `구현현황_정리.md` 7.3 답변

| 항목 | 답 |
|---|---|
| (1) 한도의 단위 | **칸(종류) 수.** 종류 1개 = 1칸, 한 칸에 최대 `MaxStack`(기본 999)개. 기본 16칸, 최대 40칸 (`InventoryConfig`) |
| (2) 꽉 찼을 때 수확 | 권장안대로 `GetAddableAmount`로 먼저 확인하고, 안 되면 수확하지 않는다. 이미 가진 작물은 칸이 꽉 차도 계속 쌓인다. 해달이 계속 가려는 문제는 `FindNearestAwaitingHarvestSlot`에서 같은 확인을 하면 된다 |
| (3) 레벨 | **레벨이 아니라 구매로 확장한다.** 잠긴 칸을 누르면 유료 재화(조개/Gem) 100개로 4칸 확장 (`InventoryManager.TryPurchaseExpansion`). 레벨과 묶을지는 나중에 기획으로 정한다 |
| (4) 아이템 설명 데이터 | 공통 `ItemDefinition`이 있다 (권장안과 같음). 판매가도 여기 있으므로 `CropDefinition.sellPrice`는 판매에 쓰지 않는다 |
| (5) UI 갱신 | `Inventory.OnItemChanged` 이벤트가 있다. 가방 UI(`InventoryPresenter`)는 이미 이걸로 자동 갱신된다 |
| (6) UI 클릭 겹침 | 인벤토리는 uGUI다. 밭 쪽 `FurrowSlotView.HandleClick`에 `EventSystem` 검사가 필요하다 (Game_Structure 담당) |
| (7) 세이브 호환 | `inventoryCapacity`가 0이면 기본 용량을 쓴다. 옛 세이브에 용량보다 많은 종류가 있어도 **버리지 않고 초과 상태를 허용하고, 새 종류 추가만 막는다** |

## 5. 결정 필요

### (1) 아이템 ID — 게임 쪽 규칙으로 통일함
세이브에 이미 `crop_carrot`, `fish_basic` 같은 ID가 쓰이고 있어서, 인벤토리 쪽 아이템 ID를 **게임 쪽 규칙에 맞춰 바꿨다.**

| ItemDefinition | ID | 게임 쪽 |
|---|---|---|
| 당근 | `crop_carrot` | `CropDefinition` ✅ 같음 |
| 감자 | `crop_potato` | `CropDefinition` ✅ 같음 |
| 고등어 | `fish_mackerel` | 게임에는 `fish_basic`(물고기)뿐 |
| 감자/고구마/딸기 모종 | `seed_potato`, `seed_sweet_potato`, `seed_strawberry` | 아래 (2) |

`ItemDefinition`이 아직 없는 게임 아이템: `crop_cucumber`, `crop_sweet_potato`, `fish_basic`, `trash_basic`. 교체 전에 인벤토리 쪽에서 만들어 둔다 (아이콘/설명 필요). 그 전에 교체해도 1장 설명대로 데이터는 사라지지 않는다.

→ **`fish_basic`을 고등어로 볼지, 별도 "물고기" 아이템으로 둘지** 정해 주면 맞춘다.

### (2) 씨앗(모종)을 가방에 넣을지
지금 게임은 씨앗 재고를 `SaveData.seeds`(cropId → 개수)에 따로 관리한다. 시안(요정상점)은 모종을 **상점에서 사서 가방에 들어오는 아이템**으로 그리고 있다.

- A. 모종을 가방 아이템으로 (`seed_*`) — 심을 때 `Inventory.TryRemove`. `SaveData.seeds`는 없앰
- B. 지금처럼 `SaveData.seeds` 유지 — 가방의 "모종" 칸은 비워 둠

→ 어느 쪽으로 할지 정해 주면 인벤토리 쪽을 맞춘다.
