# P1 — 정착 해달 노동력 + 공통 개간지역 (광산 샘플)

기준: `해달왕국_P1_개간지역_개발작업지시서.md` / 브랜치 `feature/Settlement`

> **플레이어가 새 땅에 첫 길을 열고, 정착한 해달들이 그 땅을 왕국의 공간으로 완성한다.**
> 이번 P1에서는 광산 하나로 검증했다. 지도·지역 배치·아트는 만들지 않았고, 새 지역은 **데이터만 추가**하면 붙는다.

---

## 1. 바뀐 흐름 (광산)

```text
의자 완료 (Lv.2, 광산 발견)
↓
광산으로 이동 → 나무 2 + 돌 2 직접 치움          ← 플레이어 단계 (기존과 같음)
↓
"길이 열렸어요! 망치를 눌러 해달을 보내요"        ← 여기서 바로 채굴되지 않음
↓
망치 표지판(또는 게시판 카드 / 안내 띠) → 주민 작업 화면
↓
주민 해달 1명 배치 → [작업 시작] (30초, 앱을 꺼도 흐름)
  - 광장의 그 해달은 길 끝으로 걸어 나가 광장에서 사라짐
  - 광산에서는 그 해달이 걸어와 망치 말풍선을 띄우고 일함, 위에 남은 시간
↓
작업 끝 → 광산 운영
  - 게시판 부탁 "광산 길 열기" 완료 → 왕국 Lv.3 · 새 해달(물감이·건설 해달) · 완료 팝업
  - 광산 입구가 나타나 채굴 가능, 광산 튜토리얼도 이때
  - 광산 꾸미기 구역 "광산 앞마당" 해금
  - 일한 해달은 광장으로 돌아옴
```

**Lv.3 시점**: 작업지시서 권장대로 **광산 완전 운영 완료 → Lv.3**.

## 2. 구조

| 역할 | 클래스 | 위치 |
|---|---|---|
| 작업 데이터 | `SettlementTaskDefinition` (taskId, 필요 인원, 시간, 필요 발전, 결과 발전, 완료 문구) | `Settlement/Data` |
| 지역 데이터 | `DevelopableRegionDefinition` (regionId, zone, 발견·직접개척·운영 발전 ID, 후속 정비 작업 목록, 꾸미기 격자·구역) | `Settlement/Data` |
| 꾸미기 해금 조건 | `DevelopmentUnlockRequirement` (UnlockRequirement 상속, "광산 정비를 마치면") | `Settlement/Data` |
| 상태(순수 C#) | `Settlement` 에 진행 중 작업 · 끝낸 작업 추가, `SettlementTaskJob` | `Settlement/Model` |
| 규칙 | `SettlementRegionRules` (지역 단계, 작업 상태, 보낼 수 있는 해달) | `Settlement/Model` |
| 조율 | `SettlementManager` "개간 지역 · 주민 작업" 구역 | `Settlement` |
| 광산 화면 | `ZoneClearingView`(단계별 안내), `RegionTaskSiteView`(망치 표지판·남은 시간), `RegionWorkerView`(일하러 온 해달) | `Settlement/World` |
| 작업 화면 | `SettlementTaskPopupView` + `WorkerChipView` + `SettlementTaskPresenter` (전역 UI) | `Settlement/UI` |

### 지역 단계 (`RegionProgressState`)
`Locked → Discovered → PlayerClearing → AwaitingWorkers → WorkerPreparing → Operational`

단계는 **따로 저장하지 않고 발전 + 작업 상태로 정한다** (둘이 어긋날 일이 없음):
- 발견 = `discoverDevelopment` (광산: `chair`)
- 직접 개척 완료 = `playerClearDevelopment` (광산: `mine_path_open`)
- 운영 = `operationalDevelopment` (광산: `mine_cleared` = 원래 "광산 길 열기" 부탁의 결과)
- 정비 중 = 후속 작업 중 하나가 진행 중

### 역할 분리 (작업지시서 21-4)
- **해달의 부탁** (`BoardRequestDefinition`) = 메인 진행 (광산 길 열기는 운영될 때 완료)
- **주민 작업** (`SettlementTaskDefinition`) = 주민 노동력 (`QuestManager`와 무관)
- **퀘스트** = 반복 행동 보상 (변경 없음)

### 노동력 규칙 (단순하게)
- 보낼 수 있음: `ResidentState.Resident` + 지금 다른 작업 없음 + 공사를 직접 하러 가 있지 않음
- 보낼 수 없음: 방문객, 정착 후보, 건설 해달(큰 공사 담당), 이미 작업 중인 해달
- 해달 작업 상태 `ResidentWorkState`(Idle / Working)는 진행 중 작업에서 계산 (`ResidentState`와 분리)
- 피로도·능력치·효율 같은 수치는 없음

## 3. 세이브

`SaveData.settlement` (스키마 변경 없음, 새 목록은 옛 세이브에서 비어 있음):

```text
SettlementSaveData
 ├ residents / completedRequests / unlockedDevelopments (지역 단계도 여기서 정해짐)
 ├ tasks          진행 중 작업: taskId, startUtcTicks, endUtcTicks, assignedOtterIds
 └ completedTasks 끝낸 작업
```

- 끝나는 시각(UTC)을 저장 → 앱을 꺼 둔 동안 끝났으면 다음 실행 때 완료 처리 (건설과 같은 방식), 돌아옴 팝업 소식에도 나옴
- 깨진 줄(같은 해달이 두 작업, 해달 없음, 이미 끝낸 작업)은 불러올 때 버림 → 해달이 묶이지 않음
- 옛 세이브: 이미 광산을 연 세이브는 `mine_cleared`가 있어 그대로 운영, 꾸미기 구역도 불러올 때 맞춰 열림

### 꾸미기 세이브 연결 (팀원 확인 부탁)
`꾸미기_연동요청_클로드전달용.md`에 적어 둔 그대로 `GameManager`에 연결했다 (P1 체크리스트 "재접속 후 배치 유지" 때문):
- `SaveData.decor` 추가
- `LoadGlobalProgressOnce`: 가방 뒤 · 정착 앞에서 `DecorManager.LoadFromSave` (`loadedDecor`로 한 번만)
- `SaveNow`: `DecorManager.WriteToSave`
- 꾸미기 모드 [완료] 때 바로 저장 (`DecorManager.SaveRequested`)

## 4. 새 지역 붙이는 법 (숲·밭·낚시터·광장 외곽)

1. `SettlementTaskDefinition` 에셋 (예: 숲 길 정리, 필요 2명, 40초, 필요 발전 `forest_path_open`)
2. `DevelopableRegionDefinition` 에셋 (zone, 세 발전 ID, 작업 목록, 꾸미기 격자·구역)
3. `SettlementConfig`의 `_regions`, `_tasks`에 추가
4. 그 장소 씬에 `ZoneClearingView`(장애물) + `RegionTaskSiteView`(정비 현장) — 광산은 `SettlementSetup.PlaceMine`이 만듦
5. (선택) 그 장소의 직접 치우는 부탁(`BoardRequestDefinition._clearZone`) — 있으면 운영될 때 부탁이 끝나 레벨·새 해달 연출

지도는 나중에 `MapNode.regionId = "region_mine"`처럼 **regionId만 가리키면** 된다. 지역 데이터에는 좌표·그림·연결선을 넣지 않았다.

## 6. 확인한 것

- EditMode 211개 통과 (새로 `SettlementTaskTests` 8개: 지역 단계, 보낼 수 있는 해달, 중복 배치, 한 번만 완료, 세이브 왕복, 깨진 줄, 옛 세이브)
- PlayMode 흐름: 광산 장애물 제거 → AwaitingWorkers(부탁 미완료·입구 숨김·꾸미기 잠김) → 작업 화면에 몽실 미리 선택 → 시작 → 광산에 해달 등장·남은 시간 → 광장에서 몽실 없음 → 완료 → Operational · 부탁 완료 · Lv.3 · 꾸미기 해금 · 몽실 복귀 → 광산 입구 · 장난감 배치 · 세이브에 기록
- 광장에서 작업을 시작하면 몽실이가 길 끝으로 걸어가 사라짐 (길을 못 찾아도 12초 뒤 광장에서 빠짐)

## 7. UI 그리는 순서 (함께 정리)

| 순서 | 캔버스 | 내용 |
|---|---|---|
| 90 | 장소 화면 `GameUI`의 ScreenLayer | 곡괭이·낚싯대 강화 버튼, 장소 안내 말풍선 |
| 100 | 전역 UI `GlobalUI` | 상단바·하단바, 게시판·작업·완료·레벨업 팝업 |
| 200 | 장소 화면 `GameUI` | 장소 팝업 (곡괭이 강화, 오프라인 보상 등) |
| 500 | `TutorialOverlay` | 튜토리얼 |
| 1000 | `ScreenFader` (구름 전환) | 씬 전환 중에는 모든 UI를 덮음 |

- 팀원 파일 `GameUI.cs` 수정: 강화 버튼·안내 말풍선을 아래 층(90)으로 옮김 → 전역 팝업과 구름이 덮음. 장소 팝업은 그대로 200.
- 구름 전환: 씬을 불러오느라 멈춘 시간이 첫 프레임에 몰려 걷히는 연출이 건너뛰어지던 것을 막음 (한 프레임 최대 1/30초).
- 비용 없이 끝낸 부탁(광산 길 열기) 완료 팝업은 비용 칸 자리에 부탁 그림.

## 8. 보류 (작업지시서 20)

최종 월드맵, 지역 실제 배치, 광장 외곽 확장(카메라 `extraBoundsSources` 연결은 이 구조를 막지 않음), 숲·평야·호수 씬, 밭·낚시터 개척 방식 변경, 지역별 장식 카탈로그, 개간지역 최종 아트.
광산 작업 B("작업 공간 평탄화", 2명)는 그때 주민이 1명뿐이라 넣지 않았다 — 지역에 작업을 하나 더 넣으면 바로 동작한다.
