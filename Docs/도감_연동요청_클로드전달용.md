## 0. 요약

도감 화면을 레퍼런스대로 만들었다. 네비게이션 바의 **도감** 버튼으로 열린다. 채소·어류는 **가방에 처음 들어오면 자동으로 획득**된다.

**부탁할 것은 2장이다.** 세이브 연결은 꼭 필요하고, 해달 등록과 방문 흔적은 해달 기능에 맞춰 연결하면 된다.

---

## 1. 동작 방식

### 1.1 구성 (레퍼런스와 같음)

- 위쪽: 큰 그림, 이름, 상태 배지(획득 완료 / 등록 완료 / 방문 흔적), 한 줄 소개, 설명 박스(설명 + "획득 장소" 또는 "좋아하는 것")
- 가운데: 채소 / 어류 / 해달 탭 (선택된 탭은 금색)
- 아래쪽: 4열 목록, `수집 2/4` 또는 `등록 1/2 · 방문 흔적 1`, 맨 아래 범례
- 아직 얻지 못한 항목은 이름을 `???`로, 그림을 실루엣으로 가린다. 방문 흔적은 이름만 공개하고 그림을 반투명으로 보여준다.

### 1.2 지금 들어 있는 항목

`Assets/Scriptable Obejects/Collection/Entries/`

| 탭 | 항목 ID | 자동 획득 |
|---|---|---|
| 채소 | `crop_carrot`, `crop_potato`, `crop_sweet_potato`, `crop_cucumber` | 같은 ID의 아이템이 가방에 들어오면 |
| 어류 | `fish_mackerel` | 같은 ID의 아이템이 가방에 들어오면 |
| 해달 | `otter_farmer`, `otter_fisher` | 없음 (게임 쪽이 호출, 2장 (2)) |

- 쓰레기와 모종은 도감에 넣지 않았다.
- 레퍼런스의 12칸은 예시라서, 실제 항목 수만큼만 보인다.
- 항목을 추가할 때는 에셋만 만들면 된다. `Tools > Navigation > Build Global UI`를 실행하면 DB에 자동으로 등록된다.

### 1.3 자동 획득 규칙

- 연결된 아이템의 개수가 **늘어나면** 획득한다. 수확, 낚시, 오프라인 수확, 세이브 복원(`ItemChangeReason.Load`)을 모두 포함한다.
- 팔거나 써서 줄어드는 건 도감과 상관없다. 한 번 획득하면 되돌아가지 않는다.
- 도감이 생기기 전의 세이브도 괜찮다. **이미 가방에 있는 아이템은 시작할 때 모두 획득 처리한다.**

### 1.4 도감 모델의 위치

- `CollectionManager`는 **`GlobalUI` 프리팹 루트에 붙어 있다.** 씬에 따로 배치할 필요가 없다.
- `[DefaultExecutionOrder(-90)]`로 `InventoryManager`(-100) 다음, `GameManager`(0)보다 먼저 준비된다.

## 2. 부탁할 것

### (1) 세이브 연결 — 필수

지금은 도감 상태를 저장하지 않는다. 채소·어류는 가방에서 다시 채워지지만, **가방에서 다 판 아이템과 해달 상태는 앱을 다시 켜면 사라진다.**

```csharp
// SaveData
public List<CollectionSaveEntry> collection = new List<CollectionSaveEntry>();

// 불러오기: 가방을 불러온 다음 (가방에 있는 것도 획득으로 맞춰 준다)
CollectionManager.Instance.LoadFromSave(save.collection);

// 저장: SaveNow 안에서
CollectionManager.Instance.WriteToSave(save.collection);
```

- `CollectionSaveEntry`는 `entryId`(string)와 `state`(`Visited` 또는 `Collected`)를 가진다. 미획득은 저장하지 않는다.
- DB에 없는 ID도 버리지 않고 다음 저장 때 그대로 다시 쓴다. 가방 세이브와 같은 원칙이다.
- 옛 세이브에 `collection`이 없으면(null) 빈 목록으로 바꿔서 넘겨 달라.

### (2) 해달 등록과 방문 흔적 — 해달 기능에 맞춰

```csharp
CollectionManager.Instance.Register("otter_farmer");    // 등록 완료: 온라인에서 눌러 등록, 가챠
CollectionManager.Instance.MarkVisited("otter_fisher"); // 방문 흔적: 오프라인 동안 왔다 감
```

- 둘 다 이미 그 상태 이상이면 아무것도 하지 않는다 (등록된 해달은 방문 흔적으로 내려가지 않음). 새로 바뀌었으면 `true`를 돌려준다.
- 없는 ID면 경고 로그를 남기고 `false`를 돌려준다.
- **도감 항목 ID와 해달 `speciesId`를 같게 쓰는 것을 제안한다.** 지금 도감에는 `otter_farmer`, `otter_fisher` 두 마리가 있다. 해달 데이터가 정해지면 그 ID에 맞추고, 새 해달은 도감 항목 에셋을 추가하면 된다.
- 게임 시작 때부터 있는 농부 해달과 낚시꾼 해달을 처음부터 "등록 완료"로 둘지는 그쪽 설계에 맡긴다. 그렇게 할 거면 첫 실행 때 `Register`를 호출하면 된다.
