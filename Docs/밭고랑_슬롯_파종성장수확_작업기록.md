# 밭고랑 슬롯형 파종/성장/수확 — 작업기록

작성일: 2026-09-23
문서 성격: 클로드와의 대화에서 진행한 작업 로그. 기획 확정 문서가 아니라 **다음 작업 재개 시 참고용 기록**이다. 기획 자체는 `해달마을_클로드전달용_상세기획서.md`, `해달왕국_클로드전달용_기획변경명세.md`를 기준으로 하고, 이 문서는 `M1_밭구현_작업기록.md` 이후 실제로 어떤 대화·결정·구현이 있었는지를 남긴다.

## 1. 이번 세션에서 확정된 사항

M1 문서의 "밭 1개 = 작물 1개, 클릭하면 디버그 패널 토글" 구조를 폐기하고 아래로 교체했다.

- **밭고랑 하나당 최대 3개 슬롯**. 각 슬롯이 독립적으로 파종/성장/수확된다.
- **슬롯 개별 클릭 → 작물 선택 팝업 → 선택 시 그 슬롯에 파종**. 밭고랑 전체를 클릭해서 디버그 패널을 여는 옛 방식은 삭제.
- **재배시간 10초 → 30초**, 10초마다 씨앗 → 약간 성장 → 완전 성장 스프라이트 전환 (3등분).
- **자동 수확 없음**. 다 자라면 "수확 대기" 상태로 멈추고, 외부(향후 해달 NPC)가 호출하는 `Harvest()` 트리거로만 수확된다. NPC 이동/판단 AI는 이번 범위 밖 — 지금은 디버그 패널의 수확 버튼이 그 트리거를 대신 호출한다.
- **수확이 끝나야 재파종 가능** (수확 대기 중엔 새 씨앗 못 심음).
- **슬롯 구조 확인**: 사용자가 준 4번째 이미지(점선 타원)는 슬롯 1개 전체를 나타내는 이미지이고, 이 슬롯 3개는 기존 `Plot_1_Active` **안에 새로 배치되는 자식 오브젝트**다 (기존 `Plot_1/2/3` 세 오브젝트를 슬롯으로 재활용하는 방식이 아님 — 이미지 크기가 `plot_active.png`와 비슷해서 처음엔 헷갈렸지만, 사용자가 "Plot_1_Active 안에 슬롯 3개를 새로 배치"로 확정함).
- 범위 밖으로 명시: 밭고랑 자체의 잠금 해제(구매) 플로우(`Plot_2_Locked`/`Plot_3_Locked` 안 건드림), 씨앗 구매/재화 소모, 밭 강화 시스템 변경(기존 `durationMultiplierByLevel` 그대로 유지).

## 3. 아트 에셋 파이프라인

사용자가 4장 제공: 씨앗(1장에 3연출), 중간성장(1장에 3연출), 완숙(1장에 3연출), 빈 슬롯 점선 타원(1장).

- Python/PIL로 1~3번 이미지를 각각 가로 3등분 → `crop_carrot_{seed,sprout,grown}_{0,1,2}.png`, 4번은 자르지 않고 `slot_empty.png`로 저장. `Assets/Art/Farm/Crop/`에 위치.
- 각 PNG에 `.meta`를 `plot_locked.png.meta`를 템플릿 삼아 새 guid로 생성 (Sprite, spriteMode single, PPU 104.5 — 기존 프로젝트 컨벤션과 통일).
- `CropDefinition`에 스프라이트를 인스펙터로 꽂을 수 있도록 `Assets/Data/Crops/CropDefinition_Carrot.asset` 신규 생성 (`baseDurationSec=30`), `Farm.unity`의 `GameManager.cropDefinitions`에도 자동으로 연결해둠. 기존에는 carrot이 코드에서 즉석 생성되는 fallback뿐이라 스프라이트를 못 꽂는 상태였음.

### 3-1. 크기 문제 → 여백 트리밍 + 리사이즈

슬롯에 심긴 당근이 너무 작게 보인다는 피드백. 원인은 FurrowSlotSetup 에디터 툴이 슬롯 오브젝트의 `localScale`을 밭고랑 너비 대비 30%가 되도록 계산해서 넣었는데(≈0.28), 원본 이미지에 빛 번짐 여백이 커서 실제 당근 그림 자체는 훨씬 작게 보였던 것.

- 9장(씨앗/새싹/완숙×3)을 알파값 40 이하인 여백을 기준으로 트리밍(내용 bbox + 20% 패딩).
- `slot_empty.png`는 긴 타원 도안 자체가 캔버스 대부분을 차지해서(여백 문제가 아니라 원래 그렇게 그려짐) 트리밍만으론 부족 — 1806px → 580px 폭으로 추가 리사이즈해서 작물 스프라이트들과 비슷한 스케일로 맞춤.
- `FurrowSlotSetup.cs`에서 `slotScale` 계산 로직을 제거하고 슬롯 `localScale`을 항상 `Vector3.one`으로 고정 — "올바른 크기"는 이제 이미지 픽셀 크기 자체에 미리 반영됨. 재실행해도 기존 `Slot_0/1/2`를 지우고 새로 만들도록 안전장치 추가.

### 3-2. 위치 문제 → 피벗을 하단 중앙으로 변경

크기는 맞았는데 당근이 살짝 아래쪽(땅에 박힌 것처럼)에 그려진다는 피드백. 원인은 전체 스프라이트가 피벗 **정중앙(0.5, 0.5)**이었는데, 완숙 당근처럼 잎이 위로 크게 뻗은 이미지는 "이미지 중앙"이 잎 쪽으로 치우쳐 있어서 뿌리가 중앙보다 아래에 위치 — 슬롯 위치에 이미지 중앙을 맞추면 실제 뿌리는 그보다 더 아래로 내려감.

- 10장(씨앗/새싹/완숙×3 + 빈 슬롯) 전부 `.meta`의 `alignment: 9`(Custom) + `spritePivot: {x: 0.5, y: 0}`(하단 중앙)로 변경. 성장 단계가 바뀌어도 "뿌리가 땅에 닿는 지점"이 항상 같은 기준선에 맞고, 자랄수록 위로만 커지게 됨.
- 스프라이트 임포트 설정만 바꾼 거라 씬은 다시 안 건드려도 됨 (Unity가 자동 재임포트).
- ⚠️ 두 수정 다 클로드가 렌더링 결과를 직접 볼 수 없는 상태에서 픽셀 계산만으로 추정한 값이라, 실제로 봤을 때 여전히 어긋나면 추가 조정 필요.

## 4. 씬 배선 — `Assets/Editor/FurrowSlotSetup.cs`

손으로 `.unity` YAML을 고치는 대신 에디터 툴을 새로 만들었다 (기존 `Assets/Editor/FarmerOtterSpriteSetup.cs` 패턴과 동일하게, 씬에 실제로 붙은 오브젝트를 런타임에 측정해서 정확하게 배치).

- 메뉴: `OtterKingdom > Tools > Setup Furrow Slots` (Farm.unity 열어둔 상태에서 실행).
- `Plot_1_Active`의 실제 `SpriteRenderer` bounds를 읽어 3개 슬롯 위치를 균등 배치, 기존 `BoxCollider2D`/`PlotClickToggle`(미싱 스크립트로 남아있던 것) 제거, 슬롯마다 `SpriteRenderer`(기본 `slot_empty.png`) + `BoxCollider2D`(trigger) + `FurrowSlotView`(plotIndex=0, slotIndex=0/1/2) 부착.
- 재실행해도 안전 (이전에 만든 `Slot_0/1/2`를 지우고 새로 생성).

## 5. 버그: 옛 세이브 파일과의 스키마 불일치

사용자가 Play 모드에서 `ArgumentOutOfRangeException: Index was out of range` 반복 발생 리포트. 원인은 M1 단계에서 이미 플레이해서 로컬에 남아있던 `save.json`이 옛 `PlotSaveData` 포맷(activeCropId/state/remainingSec 등, slots 필드 없음)이었고, `JsonUtility.FromJson`이 이를 새 클래스로 읽으면 `slots`가 빈 리스트(0개)로 남아서 `FurrowSlotView`가 매 프레임 `Data.slots[0]`을 읽으려다 터진 것.

- 수정: `FarmService` 생성자에서 각 `PlotSaveData`를 `PlotRuntime`으로 감싸기 전에 `slots.Count`가 `PlotSaveData.SlotCount`(3)에 못 미치면 빈 슬롯으로 채워 넣는 정규화(`NormalizeSlots`)를 추가. 세이브 파일을 지우라고 안내하는 대신 코드 레벨에서 자체 치유되게 함 — 앞으로 세이브 포맷이 또 바뀌어도 같은 방식으로 안전.

## 6. 아직 안 한 것 / 다음 후보

- **해달 NPC 이동/자동 수확 AI**: 이번 범위 밖. `FarmService.Harvest(plotIndex, slotIndex)`가 트리거 인터페이스로 준비되어 있으니, NPC가 슬롯 근처에 도착했을 때 이 메서드만 호출하면 됨. (⚠️ 메모리에 다른 세션에서 `FarmerOtterController.cs`로 이 부분을 이미 구현한 기록이 있음 — 이 세션의 작업물이 아니므로 통합 여부는 다음 재개 시 확인 필요.)
- **밭고랑 2/3번 잠금 해제(구매) 플로우**: 손 안 댐. 지금 만든 슬롯 시스템은 범용으로 짜여 있어서 나중에 2/3번 밭고랑이 열리면 그대로 재사용 가능.
- **씨앗 구매/재화 소모**: 파종은 지금 무료·즉시. 상점/요정 상인 연동 시 다시 설계 필요.
- **사용자가 아직 확인 안 한 것**: `OtterKingdom > Tools > Setup Furrow Slots` 재실행 후 슬롯 위치/크기가 실제로 맞는지, 피벗 수정 후 당근이 제대로 된 위치에 그려지는지 — 클로드가 렌더링을 직접 볼 수 없어서 수치 계산으로만 추정했음.
