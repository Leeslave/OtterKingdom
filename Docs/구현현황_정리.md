## 3. 코어 시스템

### 3.1 GameManager (`Assets/Scripts/GameManager.cs`)

Farm 씬에 있는 싱글톤. 게임 전체를 여기서 조립한다.

- **Awake**
  - 작물/밸런스 데이터가 비어 있으면 기본값(당근 30초, 수확량 5, 판매가 2)을 코드로 만든다.
  - 세이브 파일을 불러오고, 없으면 새 세이브를 만든다 (밭 `plot_1` 해금, 슬롯 3개 비어 있음, 해달 `otter_001`).
  - 마지막 저장 시각과 현재 시각의 차이로 오프라인 경과 시간을 계산한다.
  - `CurrencyManager`에 세이브의 코인 잔액을 넣고, 상단 코인 HUD를 띄운다.
  - `InventoryService`, `FarmService`를 만든다.
- **Start**: 오프라인 경과 시간만큼 밭을 한 번에 진행시키고 저장한다.
- **Update**: 매 프레임 밭 시간 진행, 30초마다 자동 저장.
- **OnApplicationPause / OnApplicationQuit**: 저장.
- **외부에 공개하는 기능**
  - `HarvestSlot(plotIndex, slotIndex)`: 수확 공용 진입점. 밭에서 수확 → 가방에 추가 → 저장. 디버그 버튼과 농부 해달이 둘 다 이걸 부른다.
  - `RequestPlantPrompt(plotIndex, slotIndex)`: 빈 슬롯을 눌렀을 때 작물 선택 팝업을 연다.
  - `IsScreenPointOverUI(screenPos)`: 화면 좌표가 OnGUI 패널 위인지 확인 (패널 클릭이 뒤의 슬롯까지 눌리지 않도록).
  - `ToggleDebugPanel()`: 디버그 패널 열기/닫기. **현재 이걸 부르는 곳이 없어서** 기본 상태로는 디버그 패널이 보이지 않는다.

**임시 OnGUI 디버그 UI** (정식 uGUI로 교체 예정)
- 작물 선택 팝업: 등록된 작물 버튼 목록 + 취소
- 디버그 패널: 코인, 농사 레벨, 밭 1의 슬롯별 상태(비어있음 / 성장 중 남은 시간 / 수확 대기 + 수동 수확 버튼), 가방 목록, 전체 판매, 농사 강화, 지금 저장

### 3.2 저장 (`Assets/Scripts/Save/`)

- `JsonUtility` 사용, `Application.persistentDataPath/save.json`에 저장.
- 저장 순서: `save.json.tmp`에 먼저 쓰기 → 기존 파일을 `save.json.bak`으로 복사 → tmp를 본 파일로 교체.
- 불러올 때 본 파일이 깨졌으면 `.bak`에서 복구, 둘 다 없으면 새 게임.
- Dictionary를 쓰지 않고 class + List 구조로만 저장한다 (팀 규칙).

**SaveData 구조 (schemaVersion 1)**

```
SaveData
├─ schemaVersion : int = 1
├─ lifetimeSales : int              // 누적 판매액
├─ farmLevel     : int = 1          // 농사 강화 레벨
├─ lastSaveUtc   : string (ISO-8601)
├─ plots         : List<PlotSaveData>
│   └─ plotId, unlocked, workerId, slots: List<FurrowSlotSaveData>
│       └─ cropId, state(Empty/Growing/AwaitingHarvest), remainingSec
├─ inventory     : List<ItemStack>  // itemId, quantity
├─ otters        : List<OtterSaveData>  // instanceId, speciesId, unlocked
└─ currencies    : List<CurrencyBalance> // currencyId, amount
```

**아직 없는 것**: 오프라인 최대 8시간 제한, 시계 되돌리기 방지, 모르는 아이템 ID 처리(마이그레이션), 손상 시 사용자 안내 UI, schemaVersion에 따른 마이그레이션 로직.

### 3.3 재화 (`Assets/Scripts/Currency/`)

- `Currency` (ScriptableObject): ID, 표시 이름, 설명, 아이콘, 최대/최소 보유량. 에셋은 `Assets/Scriptable Obejects/Gold.asset` 하나.
- `CurrencyManager` (자동 생성 싱글톤, 씬 넘어가도 유지)
  - `Add` / `TrySpend` / `ProcessTransaction`: 거래 적용. 결과 잔액이 최대/최소를 벗어나면(예: 잔액 부족) 적용하지 않고 `false`.
  - 거래마다 출처(`TransactionSource`: CropSale, FarmUpgrade, TestGet 등)와 배율을 기록. 배율 버프 계산 자리(`ApplyGlobalModifiers`)는 비어 있다.
  - `OnCurrencyChanged` 이벤트로 UI에 알림.
  - `LoadFromSave` / `SaveToSave`로 세이브의 `currencies` 목록과 연동.
- `CurrencyHud`: 런타임에 코드로 만드는 화면 상단 "코인 N" 표시. 씬 설정 없이 뜬다.
- `CurrencyUI`: 인스펙터에 연결해 쓰는 TMP 기반 재화 표시 (숫자가 올라가는 애니메이션). 프리팹은 `Assets/Prefabs/UI/CurrencyUI`.
- `TestCurrencyUI`: 입력한 숫자만큼 재화를 더하는 테스트 도구.

> 표시 이름은 "코인"으로 통일하기로 했지만 `Gold.asset`의 `DisplayName`은 아직 "골드이", `CurrencyID`는 "1"이다. 정리 필요.

## 4. 밭 (Farm)

### 4.1 데이터

- `CropDefinition` (ScriptableObject, `Assets/Data/Crops/`): 작물 ID, 이름, 기본 성장 시간, 수확량, 판매가, 씨앗 종류, 성장 단계별 스프라이트(씨앗/새싹/다 자람, 슬롯 0~2별로 따로).
  - 현재 에셋: `CropDefinition_Carrot` (당근, 30초, 5개, 개당 2코인, 영구 씨앗)
- `SeedType`: `Permanent`(무한) / `Consumable`(소모). **값만 정의되어 있고, 소모형 씨앗의 재고 차감은 구현되지 않았다.**
- `FarmBalanceData` (ScriptableObject): 강화 비용 `30 / 150 / 500 / 1200`, 레벨별 성장 시간 배율 `1.0 / 0.9 / 0.8 / 0.7 / 0.6`, 최대 레벨 5, `storageCapacityCycles = 6`.
  - Farm 씬의 `GameManager`에 에셋이 연결되어 있지 않아 코드 기본값을 쓴다.
  - `storageCapacityCycles`는 정의만 있고 **어디서도 쓰지 않는다.**

### 4.2 로직

- 밭(고랑) 하나에 독립된 슬롯 3개 (`PlotSaveData.SlotCount = 3`).
- 슬롯 상태: `Empty` → `Growing` → `AwaitingHarvest` → (수확) → `Empty`.
- 성장 단계(보여주기용): 경과 시간 기준으로 1/3씩 `Seed` → `Sprout` → `Grown`.
- 성장 시간 = `올림(기본 시간 × 강화 레벨 배율)`. 심는 순간의 레벨로 정해진다.
- 다 자라면 수확 대기 상태로 멈춘다. 자동으로 다시 심지 않는다.
- 수확은 외부(농부 해달 또는 디버그 버튼)에서 `HarvestSlot`을 불러야만 일어난다.
- 옛 세이브의 슬롯 수가 모자라면 불러올 때 빈 슬롯으로 채운다.
- 해금되지 않은 밭에는 심을 수 없다. 밭 해금 기능 자체는 아직 없다 (`Plot_2`, `Plot_3`는 잠김 이미지만).

### 4.3 화면 (`FurrowSlotView`)

- 슬롯마다 붙는 컴포넌트. 상태/단계가 바뀔 때만 스프라이트를 바꾼다.
- **빈 슬롯을 누르면** 작물 선택 팝업이 뜬다 (Input System의 `Pointer` 사용, 터치·마우스 모두).
- 성장 중이거나 수확 대기인 슬롯은 눌러도 반응하지 않는다.

### 4.4 농사 강화

- 디버그 패널의 "농사 강화" 버튼 → 코인 차감 → `farmLevel + 1`.
- 효과는 성장 시간 단축뿐. 레벨 5가 최대.
- 인벤토리 확장과 연결되는 "레벨"은 아직 없다 (7.3 참고).

## 5. 농부 해달 NPC (`View/FarmerOtterController.cs`)

- **배회**: 인스펙터에 넣은 웨이포인트 중 무작위로 골라 걸어간다. 도착하면 랜덤 동작(`Net` 잠자리채, `Stretch` 기지개, `Eat` 먹기, `Squat` 쪼그려 앉기) 중 하나를 재생한다. 목록이 비어 있으면 Idle로 1.5~4초 대기.
- **자동 수확**: 수확 대기 슬롯이 생기면 배회를 멈추고 가장 가까운 슬롯으로 간다 → `Harvest` 애니메이션 → **애니메이션이 끝난 뒤에** `GameManager.HarvestSlot` 호출 → 다시 배회.
  - 걸어가는 동안 다른 경로로 이미 수확됐으면 조용히 배회로 돌아간다.
- **이동**: 대각선 대신 세로 먼저, 가로 나중 (밭 테두리를 가로지르지 않도록). 방향에 따라 `Walk_Side/Down/Up` 애니메이션, 좌우는 스프라이트 뒤집기.
- 애니메이션 재생 속도(걷기/수확/랜덤 동작)를 인스펙터에서 조절 가능.
- 정렬 순서 2 고정 (밭 0, 슬롯 1보다 위). 밭 2·3까지 걸어다니게 되면 Y 기준 정렬로 바꿔야 한다.

## 6. 광장 (Plaza) — 프로토타입

광장 씬은 게임 데이터(세이브, 해달 보유 목록)와 연결되지 않은 독립 프로토타입이다.

- **`PlazaController`**: 시작 시 `PlazaSettings.otterCount`(기본 5)마리의 해달을 이동 가능한 곳에 서로 떨어뜨려 배치. 그중 3마리는 첫 화면에 보이도록 카메라 근처에 둔다. 무작위 배치가 실패하면 미리 둔 스폰 포인트를 쓴다.
- **`OtterWanderAgent`**: 대기 → 걷기 → 대기 반복. 해달마다 대기 시간·걷는 속도가 달라 동시에 움직이지 않는다. 목적지 경로는 한 번만 계산하고, 오래 걸리면(막힘) 포기하고 다시 대기.
- **`OtterVisualController`**: 이동 방향에 맞춰 걷기 애니메이션·좌우 반전, 발 위치 Y 기준으로 앞뒤 정렬.
- **`PlazaWalkableArea`**: 손으로 그린 이동 가능/불가 폴리곤을 격자로 바꿔 두고, 길찾기(A* + 경로 다듬기), 도달 가능한 목적지 고르기, 연결된 영역 판별을 처리한다. 해달 몸 폭만큼 벽에서 여유를 둔다.
- **`PlazaAreaPolygon`** + 에디터(`PlazaAreaPolygonEditor`): 씬 뷰에서 꼭짓점 드래그/추가/삭제로 영역 편집.
- **`PlazaProp`** + **`PlazaDepth`**: 나무·집 같은 소품과 해달이 같은 규칙(화면 아래쪽일수록 앞)으로 정렬돼, 해달이 나무 뒤로 지나가거나 앞으로 나올 수 있다. 돗자리 같은 바닥 소품은 항상 해달 아래.
- **`PlazaCameraController`**: 드래그로 화면 이동. 배경 밖이 보이지 않게 막고, 어떤 화면 비율에서도 배경이 화면을 덮도록 확대 정도를 자동 제한. 첫 손가락만 추적, UI 위에서 시작한 드래그는 무시. 확대/축소 제스처와 관성은 없음.
- **`PlazaSettings`** (ScriptableObject): 해달 수, 크기, 스폰 간격, 대기 시간, 걷는 속도, 목적지 거리 등.

**없는 것**: 소품 배치(플레이어가 놓기), 해달 탭 반응, 세이브 연동, 보유 해달과 연동.

## 7. 🚧 인벤토리 (다른 개발자 작업 중)

### 7.1 작업 범위

1. **보유 한도**: 가방에 가질 수 있는 총 개수가 NN개로 정해져 있다.
2. **레벨업 확장**: 레벨업을 하면 보유 한도가 늘어난다.
3. **보유 아이템 목록 UI**: 가진 아이템을 목록으로 보여준다.
4. **아이템 상세**: 목록의 아이템을 누르면 선택 상태가 되고, 어떤 아이템인지 설명이 나온다.

### 7.2 지금 코드에 있는 것 (작업 출발점)

`InventoryService` (`Assets/Scripts/Inventory/InventoryService.cs`, 32줄)

| 기능 | 내용 |
|---|---|
| `Items` | 보유 목록 읽기 전용 (`IReadOnlyList<ItemStack>`) |
| `Add(itemId, quantity)` | 같은 ID가 있으면 수량 합산, 없으면 새 칸 |
| `AddRange(items)` | 여러 개 한꺼번에 추가 (수확 결과용) |
| `Clear()` | 전부 비우기 (전체 판매 후 사용) |

- 저장은 `SaveData.inventory` (`List<ItemStack>`)를 그대로 참조하므로 따로 저장 코드가 필요 없다.
- 현재 가방을 보여주는 곳은 디버그 패널의 텍스트 목록뿐 ("당근 x5").

**없는 것**: 보유 한도, 한도 초과 처리, 개별 제거/차감, 변경 이벤트, 아이템 정의 데이터(이름·설명·아이콘), 정식 UI.

### 7.3 연동할 때 확인할 부분

작업하면서 기존 코드와 맞물리는 지점이다. 결정이 필요한 항목은 **[결정 필요]**로 표시했다.

**(1) 한도의 단위** — **[결정 필요]**
지금은 같은 아이템이 한 칸에 무제한으로 쌓인다. "NN개"가 **아이템 총 수량**인지 **칸(종류) 수**인지 정해야 한다. 당근 한 번 수확이 5개이므로, 총 수량 기준이면 한도가 빨리 찬다.

**(2) 가방이 꽉 찼을 때 수확** — **[결정 필요]**
수확은 `GameManager.HarvestSlot` 한 곳에서만 가방에 넣는다. 지금은 `FarmService.Harvest`가 슬롯을 먼저 비운 뒤 `AddRange`를 부르므로, 가방이 꽉 차서 못 넣으면 **작물이 그냥 사라진다.**
- 권장: `HarvestSlot`에서 넣을 수 있는지 먼저 확인하고, 안 되면 수확하지 않고 슬롯을 `AwaitingHarvest`로 둔다.
- 그러면 `FarmerOtterController`가 같은 슬롯으로 계속 가려고 할 수 있다. 해달이 "가방 꽉 참" 상태에서는 수확하러 가지 않도록 조건을 하나 추가해야 한다 (`FindNearestAwaitingHarvestSlot`).
- 오프라인 진행은 수확까지 하지 않으므로(슬롯이 수확 대기에서 멈춤) 오프라인 쪽은 따로 손볼 필요 없다.

**(3) "레벨"이 무엇인지** — **[결정 필요]**
코드에 있는 레벨은 `SaveData.farmLevel`(농사 강화, 1~5) 하나뿐이다. 플레이어 레벨이나 가방 레벨은 없다.
- 농사 강화에 붙일지, 가방 전용 레벨(`inventoryLevel`)을 새로 만들지 정해야 한다.
- 새로 만든다면 `SaveData`에 필드를 추가하고, 비용은 `CurrencyManager.TrySpend`로 차감 (`TransactionSource`에 항목 추가). `FarmService.TryUpgrade`가 같은 패턴이라 참고하면 된다.
- 레벨별 한도 표는 `FarmBalanceData`처럼 ScriptableObject로 빼 두면 기획 조정이 쉽다.

**(4) 아이템 설명 데이터**
지금 아이템 이름은 `farmService.GetCrop(itemId).displayName`으로 작물 데이터에서 가져온다. 설명·아이콘 필드는 없다.
- 작물만 있을 때는 `CropDefinition`에 설명/아이콘을 추가해도 되지만, 앞으로 조개·물고기 같은 채집물이 들어오므로 공통 `ItemDefinition`(ID, 이름, 설명, 아이콘, 판매가)을 따로 두는 쪽이 낫다.
- 판매가 계산(`SellAllForGold`)도 지금 `CropDefinition.sellPrice`를 직접 보고 있어서, 아이템 정의를 따로 만들면 여기도 함께 바꿔야 한다.

**(5) UI 갱신**
`InventoryService`에는 변경 이벤트가 없다. 목록 UI가 수확/판매 때 자동으로 바뀌려면 `CurrencyManager.OnCurrencyChanged`처럼 `OnInventoryChanged` 이벤트를 추가하는 게 자연스럽다.

**(6) UI 클릭 겹침**
밭 슬롯 클릭은 `GameManager.IsScreenPointOverUI`로 OnGUI 패널 위인지만 확인한다. 인벤토리를 uGUI로 만들면 이 검사에 걸리지 않아, **인벤토리 창을 누를 때 뒤의 빈 슬롯도 같이 눌린다.** `FurrowSlotView.HandleClick`에 `EventSystem` 레이캐스트 검사를 추가해야 한다 (`PlazaCameraController.IsOverUI`에 같은 코드가 있다). Farm 씬에는 아직 `EventSystem` 오브젝트도 없다.

**(7) 세이브 호환**
`SaveData`에 필드를 추가하면 옛 세이브에서는 기본값(0)이 들어온다. 레벨/한도 필드는 0이 들어와도 문제가 없도록 불러온 뒤 보정하거나 필드 초기값을 1로 두어야 한다. 옛 세이브에 이미 한도보다 많은 아이템이 있을 때 어떻게 할지도 정해 두는 게 좋다 (예: 버리지 않고 초과 상태 허용, 추가만 막기).

## 9. 알려진 문제 / 정리할 것

- 디버그 패널을 여는 코드가 없다 (`ToggleDebugPanel` 호출처 없음). 판매·강화·수동 수확을 테스트하려면 임시로 연결해야 한다.
- 가방이 꽉 차는 개념이 생기면 수확 시 작물이 사라질 수 있다 (7.3-(2)).
- `Gold.asset` 이름/ID가 "코인" 결정과 맞지 않는다.
- Farm 씬에 `FarmBalanceData` 에셋이 연결되지 않았다 (코드 기본값 사용 중).
- 빌드 설정에 `Farm`/`Plaza` 씬이 없다.
- 소모형 씨앗(`SeedType.Consumable`) 재고 처리, `storageCapacityCycles`는 정의만 있고 동작하지 않는다.
- 오프라인 진행에 최대 시간 제한이 없다.
- 농부 해달의 정렬 순서가 고정값이라 밭 2·3 확장 시 Y 정렬로 바꿔야 한다.
- 광장은 저장/보유 해달과 연결되어 있지 않다.
