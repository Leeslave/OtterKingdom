# 세이브 손상 대응 작업 기록

- 작업일: 2026-09-28
- 브랜치: `feature/Game_Structure` (커밋 `5f46253` 이후, 아직 커밋 안 함)
- 확인 상태: `dotnet build`로 컴파일 성공. **Unity 플레이 모드 테스트는 아직 안 함** (아래 "테스트 방법" 참고)

## 배경

기존 `SaveService`에는 원본 기획서 11.4("손상 파일은 백업 복구를 먼저 시도하고, 실패하면 안내한다. 조용히 새 게임으로 덮어쓰지 않는다")를 어기는 문제가 네 가지 있었다.

| # | 문제 | 결과 |
|---|---|---|
| 1 | 본 파일과 백업이 둘 다 읽히지 않으면 `null`을 돌려주고 새 게임을 시작함 | 30초 뒤 자동 저장이 기존 진행 상황을 덮어씀 |
| 2 | 저장할 때마다 "현재 본 파일 → .bak"을 무조건 복사함 | 본 파일만 깨진 상태로 백업에서 복구해도, 다음 저장 때 깨진 본 파일이 멀쩡한 백업 위로 복사됨 |
| 3 | 임시 파일에 쓴 뒤 다시 읽어 확인하지 않고 바로 교체함 | 잘못 써진 파일이 본 파일이 될 수 있음 |
| 4 | "파일 없음"과 "파일 깨짐"을 모두 `null`로 돌려줌 | 첫 실행과 손상을 구분할 수 없음 |

## 동작

### 불러오기

| 상황 | 결과 (`SaveLoadStatus`) | 화면 |
|---|---|---|
| 본 파일 정상 | `Loaded` | 없음 |
| 본 파일이 없거나 깨짐 + 백업 정상 | `RecoveredFromBackup` | "저장 데이터에 문제가 있어서 이전 저장 시점으로 복구했어요." 알림 |
| 저장 파일이 아예 없음 | `NoSave` | 없음 (새 게임) |
| 파일은 있는데 전부 읽을 수 없음 | `Corrupted` | "저장 데이터 오류" 팝업 [새로 시작] / [종료] |

- `RecoveredFromBackup`일 때 깨진 본 파일은 `save.json.corrupt-yyyyMMdd-HHmmss`로 이름을 바꿔 보관한다. 백업은 복구용으로 그대로 둔다.
- `Corrupted`일 때
  - `Time.timeScale = 0`으로 게임 시간을 멈춘다 (밭 성장, 해달 코루틴). 팝업은 uGUI라 멈춘 상태에서도 눌린다.
  - `SaveService.WritesBlocked`가 켜져서 자동 저장, `OnApplicationPause`, `OnApplicationQuit`이 파일에 아무것도 쓰지 않는다.
  - **[종료]**: 에디터에서는 플레이 모드를 끄고, 빌드에서는 `Application.Quit()`. 깨진 파일이 그대로 남아 있으므로 다시 켜면 같은 팝업이 또 뜬다.
  - **[새로 시작]**: 깨진 본 파일과 백업을 `*.corrupt-*`로 보관 → 저장 잠금 해제 → 시간 재개 → 새 게임을 바로 저장.
- 깨진 파일은 어떤 경우에도 지우지 않는다. 나중에 직접 복구하거나 원인을 조사할 수 있다.

> 깨진 파일을 불러오는 시점이 아니라 [새로 시작]을 누를 때 보관 처리하는 이유: 불러올 때 바로 이름을 바꾸면, 플레이어가 [종료]를 누르고 다시 켰을 때 파일이 없는 것으로 보여 안내 없이 새 게임이 시작된다.

### 저장

1. `save.json.tmp`에 쓴다.
2. tmp를 다시 읽어서 검증한다. 실패하면 tmp를 지우고 기존 저장을 유지한다.
3. 교체
   - `save.json`이 없으면: tmp를 `save.json`으로 이동
   - `save.json`이 정상이면: `File.Replace(tmp, save.json, save.json.bak)`. 이전 본 파일이 백업이 된다. `File.Replace`를 지원하지 않는 환경에서는 복사로 대신한다.
   - `save.json`이 깨져 있으면: 깨진 파일을 `corrupt-*`로 보관하고 tmp를 이동. **백업은 건드리지 않는다.**

### 검증 기준 (`IsValid`)

`JsonUtility`는 `{}` 같은 JSON도 오류 없이 읽고 필드 기본값을 채운다. 그래서 파싱에 성공해도 아래 조건을 모두 만족해야 정상 파일로 본다.

- `schemaVersion > 0`
- `lastSaveUtc`가 비어 있지 않음 (저장할 때 항상 채워짐)
- `plots`가 1개 이상 (새 게임도 밭 1개로 시작함)
- `inventory`, `currencies`가 null이 아님

| `Assets/Scripts/GameManager.cs` | 불러온 상태에 따라 팝업을 띄우는 `ReportLoadStatus`, `StartOverAfterCorruption`, `QuitGame` |
| `Assets/Scripts/UI/GameUI.cs` | 버튼 문구를 정할 수 있는 `ShowChoice(title, message, yesLabel, onYes, noLabel, onNo)` 추가. 기존 `ShowConfirm`은 이걸 불러서 똑같이 동작함 |

`GameManager.cs`에 커밋 안 된 채 남아 있던 `goldCurrency` 미연결 검사 코드는 건드리지 않았다.

## 테스트 방법

저장 폴더(Windows 에디터): `%USERPROFILE%\AppData\LocalLow\DefaultCompany\OtterKingdom\`

먼저 한 번 플레이해서 `save.json`과 `save.json.bak`이 둘 다 생기게 한다 (저장이 두 번 이상 일어나야 .bak이 생김).

| # | 준비 | 기대 결과 |
|---|---|---|
| 1 | `save.json` 내용을 `abc`로 바꾸고 플레이 | 복구 알림, 진행 상황 유지, `save.json.corrupt-*` 생성 |
| 2 | `save.json`과 `save.json.bak`을 둘 다 `abc`로 바꾸고 플레이 | 오류 팝업, 밭과 해달이 멈춤, 30초 넘게 기다려도 파일 내용이 그대로 |
| 3 | 2번 상태에서 [종료] 후 다시 플레이 | 같은 오류 팝업이 다시 뜸 |
| 4 | 2번 상태에서 [새로 시작] | `corrupt-*` 파일 2개 생성, 새 `save.json` 저장, 게임 진행 재개 |
| 5 | `save.json` 내용을 `{}`로 바꾸고 플레이 | 1번과 같음 (깨진 파일로 판정) |
| 6 | 저장 폴더를 비우고 플레이 | 팝업 없이 새 게임 |

## 남은 일

- `corrupt-*` 파일이 계속 쌓인다. 개수 제한이나 오래된 파일 정리는 넣지 않았다.
- `schemaVersion`에 따른 세이브 변환, 모르는 아이템 ID 처리 정책은 이번 범위에서 뺐다.
- 씬마다 `GameManager`가 따로 세이브를 불러오므로, 씬 이동을 만들 때 오류 팝업이 씬마다 다시 뜨지 않는지 확인해야 한다 (지금은 씬 이동 기능이 없어서 문제가 드러나지 않음).
