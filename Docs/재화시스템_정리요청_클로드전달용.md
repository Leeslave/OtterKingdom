## 3. 작업 2: `SetBalance` 추가

`CurrencyManager.cs`에서 `GetCurrency` 메서드 바로 아래에 추가한다.

```csharp
/// <summary>
/// 잔액을 그대로 지정 (세이브 복원용). 배율 미적용, 한도 안으로 자름.
/// </summary>
public void SetBalance(Currency currency, int amount)
{
    if (currency == null) throw new ArgumentNullException(nameof(currency));

    int oldBalance = GetCurrency(currency);
    int newBalance = Math.Clamp(amount, currency.MinCapacity, currency.MaxCapacity);
    _wallets[currency] = newBalance;

    if (newBalance != oldBalance)
        OnCurrencyChanged?.Invoke(currency, newBalance);
}
```

이 함수가 필요한 이유: 지금 API로 세이브 잔액을 복원하려면 `ProcessTransaction`으로 저장된 금액만큼 "획득"시킬 수밖에 없다. 그러면 나중에 `ApplyGlobalModifiers`에 버프 배율이 들어갔을 때 **게임을 켤 때마다 잔액이 배율만큼 불어나는 버그**가 생긴다. `_wallets`와 `ApplyChange`가 private이라 바깥에서 우회할 방법도 없다.

이 함수 말고 다른 public 메서드는 추가하지 않는다.

## 4. 작업 3: `TransactionSource` 값 순서 바꾸기

`Assets/Scripts/Currency/CurrencyData.cs`에서 `2ed6c16` 버전은 아래와 같다.

```csharp
public enum TransactionSource{TestGet, TestUse, GotchaUse, ShopPurchase, BlacksmithUpgrade, CropSale, FarmUpgrade, PlotUnlock, FishingSale, RodUpgrade, InventoryExpand}
```

이것을 아래처럼 바꾼다. 새로 추가한 5개를 `InventoryExpand` **뒤로** 옮긴다.

이유: `InventoryExpand` 앞에 끼워 넣으면 그 정수값이 5에서 10으로 바뀐다. 인스펙터나 에셋에 enum으로 저장된 값이 있으면 틀어진다. 앞으로도 새 값은 항상 맨 뒤에 붙인다.

`CurrencyData.cs`의 나머지(`Currency` SO, `MinCapacity = 0`, `CurrencyTransaction`)는 건드리지 않는다.

## 9. 결과 (2026-09-28 완료)

### 무슨 문제였나
- Game_Structure(`25c42d4`)와 Inventory(`a67196c`)가 같은 재화 파일을 **서로 다른 출발점(A0)에서** 각자 고쳤다.
- Inventory 쪽이 develop을 머지하면서(`b89f1c2`) 충돌을 한쪽 버전으로만 정리했다. 그 결과 Game_Structure가 추가한 API가 사라져 **develop이 컴파일되지 않는 상태**가 됐다.
- 새로 생긴 `OtterKingdom.asmdef`에 `Unity.InputSystem` 참조가 빠져 있어서, Game_Structure 스크립트 6개도 컴파일되지 않았다.
- Git은 이런 문제를 충돌로 보여주지 않는다. 공통 조상 이후 한쪽만 파일을 고쳤으면 그쪽 버전을 조용히 가져간다. 그래서 **텍스트 충돌은 0건인데 코드는 깨지는** 상황이었다.

### 어떻게 풀었나 (B안: Inventory 설계로 통일)
| 순서 | 커밋 / 브랜치 | 내용 |
|---|---|---|
| 1 | `3c9b4f0` / feature/Inventory | `CurrencyManager`, `CurrencyUI`를 `b89f1c2` 버전으로 되돌림. `SetBalance` 추가. `TransactionSource` 값 5개를 맨 뒤로 옮김. asmdef의 InputSystem 참조 유지 |
| 2 | 이 문서가 포함된 머지 커밋 / feature/Game_Structure | `origin/feature/Inventory`를 머지하고 Game_Structure 코드를 새 API에 맞춤 (아래) |

Game_Structure 쪽 대응:
- `GameManager`
  - 판매 대금은 `EarnGold` → `ProcessTransaction`으로 넣는다. 금액이 0 이하면 호출하지 않는다.
  - 세이브를 불러올 때는 `SetBalance`로 잔액을 넣는다.
  - 저장할 때는 `GetCurrency` 값을 `save.currencies`의 Gold 항목에만 쓴다. 다른 재화 항목은 그대로 둔다.
  - 씬에 `CurrencyManager`가 없으면 에러를 한 번 로그로 남기고 비활성화된다.
- `FarmService`, `FishingService`: `TrySpend`는 비용이 0보다 클 때만 호출한다(0이면 예외가 나기 때문). Gold의 `MinCapacity`가 0이 되어서 잔액을 따로 확인하던 코드는 지웠다.
- `CurrencyHud.cs`를 `Assets/Scripts/Currency/`에서 `Assets/Scripts/UI/`로 옮겼다(GUID 유지). `Exists` 대신 `Instance != null`로 확인한다.
- `Farm.unity`, `Fishing.unity`에 `CurrencyManager` 오브젝트를 두고 `_allCurrencies`에 Gold를 연결했다. `FishingSceneSetup`도 씬을 만들 때 이 오브젝트를 넣는다. 씬마다 두는 이유는 각 씬을 바로 실행해 테스트하기 위해서다. 겹치는 것은 `Awake`에서 파괴된다.
- 확인한 것: Unity 6000.3.8f1 배치 모드에서 컴파일 에러 없음. 플레이 모드 동작은 따로 확인해야 한다.

### 지금 기준 재화 API (Game_Structure가 쓰는 것)
- `CurrencyManager.Instance`: 씬에 배치한다. 코드로 생성하지 않는다. `DontDestroyOnLoad`이고 `DefaultExecutionOrder(-100)`이다.
- `GetCurrency`, `CanAfford`, `TrySpend`(금액 1 이상), `ProcessTransaction`(배율 적용), `SetBalance`(배율 미적용, 세이브 복원용)
- `OnCurrencyChanged` (event)
- `TransactionSource`: `CropSale`, `FarmUpgrade`, `PlotUnlock`, `FishingSale`, `RodUpgrade`
- 세이브(`SaveData.currencies`)와 재화 잔액 사이의 복사는 **Game_Structure(`GameManager`)가 맡는다.** 재화 시스템은 `SaveData`를 모른다.

### 다시 이런 일이 생기지 않게
- 8장 규칙을 그대로 따른다. `Assets/Scripts/Currency/`는 choiwoohyck가 관리하고, 쓰는 쪽은 API 변경을 요청한다.
- develop을 머지할 때는 **충돌 표시가 없어도** 컴파일부터 확인한다. 특히 두 사람이 다 쓰는 폴더(`Currency/`, asmdef, `ProjectSettings`)를 조심한다.
- 충돌을 풀 때 한쪽 버전을 통째로 고르지 않는다. 판단이 어려우면 담당자에게 묻는다.
