## 0. 요약

광장·밭·낚시터에 장난감을 놓으면 해달이 **피해서 다니고**, 가끔 장난감 옆에 가서 **가지고 논다**. 밭 해달은 작물이 자라는 동안 놀다가, 수확할 게 생기면 바로 놀이를 멈추고 수확하러 간다.

이를 위해 **그쪽 파일 5개를 고쳤다**(2장). 같은 파일을 고치고 있다면 머지할 때 충돌이 날 수 있으니 알려 달라. 부탁할 것은 3장의 **세이브 연결** 하나다.

**꾸미기 모드 화면**도 있다. 하단 바 가운데 **꾸미기** 버튼을 누르면 상단바·하단 바가 숨고, 격자와 보관함이 뜬다. 보관함에서 장난감을 골라 미리보기를 끌거나 탭해서 옮기고, [확인]으로 놓는다. 놓인 장난감을 탭하면 옮기거나 [X]로 보관함에 되돌린다. [완료]로 나간다. 장난감을 빠르게 깔아 보려면 씬의 `DecorBoard` 오브젝트 인스펙터 ⋮ 메뉴 **"테스트: 장난감 지급 후 빈 칸에 놓기"**를 쓰면 된다(Play 모드).

| 데이터 | 장난감(축구공·퍼즐), 장소별 격자·구역 | `Assets/Scriptable Obejects/Decor` |

### 장소별 격자

| 장소 | 놓을 수 있는 곳 | 해달이 피하는 방식 |
|---|---|---|
| 광장 | 걷기 영역 안 (칸 1유닛) | `PlazaWalkableArea`의 장애물로 등록 → 길찾기가 피함 |
| 밭 | 흙마당. **밭고랑은 못 놓음** (`DecorBlocks/DecorBlock_Plot*`), 농부 웨이포인트·수확 자리·오프라인 NPC 자리도 비워 둠 | 곧은 길이 막히면 격자로 돌아가는 길 |
| 낚시터 | 부두 뒤쪽(바다 쪽) 한 줄. **낚시 자리는 못 놓음** (`DecorBlock_FishingSpot`) | 해달은 부두 앞쪽을 걸어서 막히지 않음 |

막는 영역(`DecorBlockArea`)은 Scene 뷰에서 빨간 상자로 보인다. 밭 레이아웃이 바뀌면 상자 크기·위치만 고치면 된다.

## 2. 그쪽 파일에서 바꾼 것 — 충돌 주의

기존 동작은 장난감이 없으면 그대로다.

### `Plaza/PlazaWalkableArea.cs`
- `SetObstacles(IReadOnlyList<Rect>)`: 실행 중 장애물(놓인 장난감)을 넣는다. `clearance`만큼 넓혀서 막고, 연결 영역(component)을 다시 계산한다.
- `IsStaticWalkable(Vector2)`: 장애물을 빼고 다각형만으로 걸을 수 있는지. 장난감을 놓을 수 있는 칸을 정할 때 쓴다.
- `Version`: 장애물이 바뀔 때마다 1 증가한다.

### `Plaza/OtterWanderAgent.cs`
- 상태 `Play` 추가. 다음에 걸어갈 곳을 고를 때 일정 확률로 장난감과 설 자리를 예약하고 그리로 걸어가 논다. 놀이가 끝나거나 끊기면 예약을 반드시 푼다.
- 걷는 중 `PlazaWalkableArea.Version`이 바뀌면(장난감을 놓거나 옮기면) 걷기를 멈추고 0.3초 뒤 다시 길을 찾는다.

### `Plaza/OtterVisualController.cs`
- `Play` 중에는 장난감을 바라보고, 컨트롤러에 있는 동작 트리거(`Squat`/`Stretch`/`Net`/`Eat`)를 하나씩 재생한다(Idle로 돌아온 뒤 다음 것).

### `View/FarmerOtterController.cs`
- 돌아다니기 사이에 일정 확률로 장난감에 가서 놀기(랜덤 동작 반복). **수확할 게 생기면 놀이를 바로 멈춘다.**
- `MoveTo`: 원래의 "세로 먼저, 가로 나중" 길에 장난감이 있으면 격자로 돌아가는 길을 따라간다(각 구간은 여전히 세로 → 가로).
- 장난감에 완전히 막힌 웨이포인트는 이번에는 건너뛴다. 수확 자리는 막혀 있어도 간다.

### `View/FishingOtterController.cs`
- `Phase`에 `WalkToPlay`, `Play`를 `GoToSpot` **앞에** 추가했다(`IsOnFishingDuty`의 `>=` 비교가 그대로 맞도록). 낚시 중이 아닐 때 장난감에 가서 놀고, 낚시를 시작하면 놀이를 바로 멈춘다.

## 3. 부탁: 세이브 연결 — 필수

지금은 놓은 장난감이 저장되지 않는다. 퀘스트·도감과 같은 방식이다.

```csharp
// SaveData
public DecorSaveData decor = new DecorSaveData();
```

```csharp
// 불러올 때 (가방을 불러온 뒤에 — 보관함 개수가 가방 개수에서 나옴)
DecorManager.Instance.LoadFromSave(save.decor);

// 저장할 때
DecorManager.Instance.WriteToSave(save.decor);
```

- 형식은 기획서 8장대로 리스트만 쓴다: 장소(`boardId`)마다 놓인 물건(배치 개체 ID, 아이템 ID, 칸 위치, 방향)과 열린 구역.
- 옛 세이브에는 `decor`가 없으니 빈 값으로 두면 된다.
- 격자가 바뀌어 자리가 맞지 않는 물건은 보관함으로 돌아간다(가방에서는 사라지지 않음).

## 4. 참고

- **장난감 아이템**: `toy_soccerball`(축구공), `toy_puzzle`(퍼즐). 가방에 새 탭 **꾸미기 > 장난감**이 생겼다. 팔 수 없는 아이템이다(`IsSellable = false`).
- **가방 칸**: 장난감은 가방 칸을 차지하지 않는다. `ItemCategory`에 "가방 칸 사용" 설정이 생겼고, 꾸미기 분류에서 꺼 두었다(하위 분류도 따라감). 가방이 가득 차도 장난감은 들어간다.
- **꾸미기 모드 중 카메라(광장)**: 미리보기를 끄는 동안에만 `PlazaCameraController`를 잠시 끈다. 다른 곳을 끌면 평소처럼 카메라가 움직인다.
- **구역 해금(확장 대비)**: 격자는 구역 단위로 잠글 수 있고, 구역마다 해금 조건(레벨, 재화 비용 등)을 에셋으로 붙인다. 지금은 모든 장소가 기본 구역 하나(전부 열림)다. 조건 없이 코드로 열려면 `DecorManager.Instance.UnlockDirectly(board, regionId)`를 쓴다.
- **놀이 애니메이션**: 전용 놀이 스프라이트가 없어서 기존 동작 애니메이션과 장난감 반응(공은 통통, 퍼즐은 흔들흔들)으로 표현했다. 전용 애니메이션이 생기면 `DecorDefinition.PlayStyle`을 기준으로 바꾸면 된다.
- **튜닝 값**: 놀러 갈 확률, 설 자리 간격, 칸 크기는 씬의 `DecorBoard` 인스펙터에서 바꾼다. 한 번 노는 시간과 동시에 놀 수 있는 수는 장난감 에셋에서 바꾼다.
