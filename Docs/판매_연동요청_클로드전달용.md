## 0. 요약

가방 상세 화면에서 아이템을 팔 수 있게 했고, **판매가 끝날 때마다 알려주는 이벤트**를 추가했다. 이제 그쪽의 임시 판매 버튼을 없앨 수 있다.

**부탁할 것은 2장이다.** 누적 판매액을 이 이벤트로 옮겨야 한다. 옮기지 않으면 가방에서 판 금액이 누적 판매액에 들어가지 않는다.

---

## 1. 동작 방식

- 가방 상세 화면의 가격 줄 오른쪽에 **[판매]** 버튼이 있다. 판매할 수 없는 아이템(`IsSellable == false`, 모종)은 가격 줄과 함께 숨긴다.
- 누르면 판매 팝업이 뜬다. 수량([−] / [+] / [최대])을 고르면 받을 금액이 바뀌고, **[판매]**로 확정한다.
- 판매는 기존 `InventoryManager.TrySell`을 그대로 쓴다. 아이템을 먼저 빼고, 그다음 골드를 준다.
- 다 팔면 목록에서 사라지고 다음 아이템이 선택된다.

### 판매 알림

```csharp
// InventoryManager
public event Action<ItemSoldEvent> OnItemSold;

public readonly struct ItemSoldEvent
{
    public readonly ItemDefinition Item;
    public readonly int Amount;      // 판 개수
    public readonly int TotalPrice;  // 판매가 × 개수 (재화 배율 적용 전)
}
```

- **`TrySell`이 성공할 때마다 한 번** 알린다. 가방 팝업이든, 그쪽 코드가 부른 `TrySell`이든, `SellAll`이든 모두 같다. `SellAll`은 아이템마다 한 번씩 알린다.
- 실패하면(판매 불가, 개수 부족) 알리지 않는다.

## 2. 부탁할 것

### (1) 누적 판매액을 이벤트로 옮기기 — 필수

지금 `GameManager`는 판매 경로마다 `save.lifetimeSales`를 직접 더한다 (`GameManager.cs` 548줄, 620줄 부근). 가방 팝업에서 판 것은 여기를 거치지 않는다.

```csharp
private void OnEnable()  => InventoryManager.Instance.OnItemSold += HandleItemSold;
private void OnDisable() => InventoryManager.Instance.OnItemSold -= HandleItemSold;

private void HandleItemSold(ItemSoldEvent e) => save.lifetimeSales += e.TotalPrice;
```

- ⚠️ **기존의 직접 더하는 코드는 지워야 한다.** 둘 다 있으면 같은 판매가 두 번 더해진다.
- `GameManager`가 씬마다 새로 생기므로, 구독과 해제를 `OnEnable`과 `OnDisable` 짝으로 해 달라. `InventoryManager`는 씬을 넘어 유지된다.

### (2) 임시 판매 버튼 정리 — 선택

밭·낚시터의 임시 판매 버튼과 판매 창은 이제 없애도 된다. 전체 판매(`SellAll`)가 여전히 필요하면 알려 달라. 가방에 "전체 판매" 버튼을 둘지 정하자.

## 3. 함께 고친 것: 숫자와 기호의 글씨체

숫자와 `?` 같은 기호가 얇은 기본 글씨체로 보이던 문제의 원인을 찾았다.

- 인벤토리 UI 일부 텍스트가 TMP 기본 폰트 **LiberationSans**를 쓰고 있었다. 한글은 LiberationSans에 없어서 TMP 설정의 기본 폰트(Cafe24)로 대신 그려졌지만, 숫자와 기호는 LiberationSans로 그려졌다.
- 인벤토리 테스트 씬, 탭·소분류 칩 프리팹, 전역 UI 생성 도구를 **Cafe24로 바꿨다.**
- 그쪽 UI에서도 숫자가 얇게 보이면 같은 원인일 가능성이 크다. TMP 텍스트의 Font Asset이 LiberationSans인지 확인해 보라.
