# 번영의 시대 — B 담당 착수 규칙 v0.1

- 작성일: 2026-11-03
- 목적: B의 P0 구현 기준과 A에게 전달할 연결 규칙을 먼저 정한다.
- 상태: 사용자 요청에 따라 정한 작업 초안. A와 합의된 것으로 간주하지 않는다.
- 근거: `번영의시대_개발분담.md`와 현재 코드. 원본 통합기획서는 아직 확인하지 못했으므로 아래 RP·연구 비용·해금 레벨은 임시 밸런스다. 원본 확인 시 차이를 기록하고 조정한다.
- 이 문서는 구현 변경이 아니다. 기존 세이브·코드·에셋은 수정하지 않는다.

## 1. 이번 목표와 범위

P0 목표는 “프롤로그 → 연구 → 첫 판재 → 창고·수레 → 주택 개량”을 Lv.20~27에서 실제로 이어 플레이하는 것이다.

- P0의 필수 기술은 I01, L01, E01, C01, I02, L02, C02의 7개로 먼저 고정한다. 분담서의 8~10개 확장은 이 흐름이 통과한 뒤 원본 기획서에서 선정한다. 새 기술 ID를 임의로 만들지 않는다.
- B는 연구·RP·진행·장터 주문·공동사업 데이터·화면·이야기·저장 전환을 맡는다.
- A의 생산 속도·수레 동작·주택 외형은 A 소유다. 요청 사항은 문서로 전달한다.
- GlobalUI.prefab과 씬을 수정하지 않고 RuntimeUIKit으로 새 화면을 구성한다.
- 기존 레벨별 필요 XP와 조개 경제는 유지한다. 이번에는 관련 없는 초반 QA 이슈를 섞지 않는다.

## 2. 자재와 소비

- `plank`, `stone_block`, `ingot`, `precision_part`는 가방 밖 왕국 창고 전용으로 정한다.
- 원재료는 현재 가방·시설 규칙을 유지한다. 같은 아이템을 가방과 창고 양쪽에서 중복 계산하지 않는다.
- 현재 IndustryConfig 기본값인 임시 보관 60개, L01 이후 총 200개를 시작값으로 쓴다. 실제 용량은 설정 데이터를 읽는다.
- 보유량은 Count, 즉시 소비 가능량은 Available로 표시·검사한다. 예약된 자재는 다른 연구·주문에서 쓰지 못한다.
- 창고 Add의 반환값은 실제 입고량이다. 남은 수량은 시설 또는 수령 대기 상태에 남기며 버리지 않는다.
- 연구·수동 납품은 최종 확인 시 전량 검사 후 소비한다. 한 재료라도 부족하면 RP·골드·자재 모두 그대로다.
- 여러 저장 영역에 걸친 비용은 B의 한 처리 단위에서 다룬다. 이벤트는 전체 성공 이후 내보낸다. 기존 창고 API만으로 가방·RP까지 원자적으로 처리된다고 가정하지 않는다.
- P0 연구에는 가공품 비용을 붙이지 않는다. 가공품 소비는 주택·꾸미기·납품에서 경험하게 해 순환 잠금을 줄인다.
- P0 수동 주문은 미리 창고 자재를 예약하지 않는다. 장기 예약·자동 계약은 예약 소유자 ID와 취소·복원 규칙을 A와 추가 합의한 뒤 사용한다. 현재 예약 API는 소유자별 예약을 구분하지 않는다.

## 3. 연구와 RP — 임시 수치

연구는 대기시간 없이 즉시 완료한다. 동일 기술은 1회만 배울 수 있다. 해금 레벨은 일찍 시도할 수 있는 하한이며, 메인 퀘스트에서 반드시 배워야 하는 시점과는 구분한다.

| 기술 | 최소 레벨 | 선행 기술 | RP 비용 |
|---|---:|---|---:|
| I01 제재 기술 | 20 | 프롤로그 완료 | 1 |
| L01 공동 창고 | 20 | I01 | 1 |
| E01 장터 주문 | 21 | I01 | 1 |
| C01 마을 정비 | 22 | I01 | 1 |
| I02 석재 규격화 | 23 | I01 | 2 |
| L02 운송 수레 | 24 | L01 | 2 |
| C02 주거 개량 1차 | 25 | C01, L01 | 2 |

- P0 필수 연구 총비용은 10 RP다. 골드·자재 추가 비용은 일단 0으로 둔다.
- 시대 진입 기본 지급: 2 RP, 지급 키 `prosperity:entry`.
- Lv.21~27 도달: 레벨마다 1 RP, 지급 키 `prosperity:level:{level}`. P0에서 총 7 RP.
- 첫 공동사업 완료 보상: 3 RP. 따라서 P0 확정 공급은 총 12 RP이며 선지급을 쓰지 않아도 필수 연구를 마칠 수 있다.
- 첫 공동사업은 Lv.20부터 접근 가능하고, 완료에 연구·가공품·수레·상위 메인 완료를 요구하지 않는다. 기존 원재료 납품과 작업으로 완료할 수 있게 설계한다. 상세 수량은 원본 확인 뒤 정한다.
- 선지급 의뢰는 연구 재료·RP가 아니라 기존 수확·채집·판매 행동으로 완료한다. P0에서 1 RP씩 최대 2회, 의뢰 ID별 1회 지급한다.
- 선지급은 미래 레벨 RP를 미리 당겨 주는 방식이다. Lv.26, Lv.27 지급분 순서로 대응시키고, 당긴 분량은 해당 레벨에서 다시 지급하지 않는다. RP 잔액이 음수가 되거나 의뢰 포기로 채무가 생기지 않는다.
- 해당 미래 지급분을 이미 받은 유저에게는 같은 선지급 의뢰를 열지 않는다.
- RP 공급표에는 선지급과 정규 지급을 별도 수입으로 합산하지 않는다.
- 일일 퀘스트·반복 주문·영상 보상으로 RP를 무한 획득하지 못하게 한다.
- 연구 가능 여부에는 레벨·선행·RP 잔액을 모두 표시한다. 조건 불충족 이유를 구체적으로 보여준다.

## 4. A와 연결하는 계약

- 기술 ID는 기존 TechIds를 사용한다. 연구 매니저는 TechGate.Provider를 연결하고, 실제 신규 연구가 성공했을 때만 NotifyLearned를 호출한다.
- 세이브 복원 시 저장된 연구 목록을 읽어 기능을 재평가한다. Learned 이벤트를 다시 쏴서 첫 보상·컷신을 중복 실행하지 않는다.
- DevLearn은 테스트용이며 저장·RP 지급·정식 퀘스트 완료의 근거로 사용하지 않는다.
- `KingdomWarehouse.Changed`는 재고 변화 알림이다. 양수 변화만 보고 “생산했다”고 세지 않는다. 수레 이동·환불·복원으로 생산량이 증가하면 안 된다.
- 제작 수량은 가공 완료 시점에 별도 누적 기록으로 저장하고, 오프라인 가공도 같은 기록 경로를 거친다. 이 기록 추가는 A에게 요청한다.
- 첫 무료 가공품은 첫 제작 체험 기록으로 인정한다. 반복 제작 수량에는 포함하지 않는 것을 기본값으로 한다.
- 기존 `first_improved_house`, `first_town_craft` 기록을 재사용한다. 같은 의미의 `house_upgraded_1` 등을 새로 만들어 병행하지 않는다.
- `first_plank`, `first_stone_block` 등 레시피가 쓰는 실제 기록 ID를 확인해 표로 고정한다. 수레 경로·자동 수거 기록은 현재 구현 확인 후 A와 이름·발생 시점을 합의한다.
- 기존 HasDevelopment로 판단 가능한 목표는 Milestone을 재사용한다. UI 문구를 ID로 쓰지 않는다.
- 오프라인은 기존 8시간 상한을 유지한다. A의 생산→보관→가공 정산 이후 B가 교역·주문을 처리한다. 같은 시간 구간을 재접속 때 다시 정산하지 않도록 마지막 정산 시점을 함께 저장한다.

## 5. 메인 퀘스트와 주문

- Lv.23~27은 레벨당 5개, 총 25개로 작성한다. 학습·실행·확장·활용·정리의 역할을 배분하되 동일 행동을 불필요하게 반복시키지 않는다.
- 한 레벨 메인 5개의 XP 합은 기존 ExpToNext(level)와 정확히 같게 한다. 기본 20%씩 정수 배분하고 마지막 퀘스트에 나머지를 준다.
- 이미 받은 XP를 마이그레이션 때 다시 주지 않는다. 일일·도전 XP가 있어도 메인 완료를 막는 최대 레벨 조건은 두지 않는다.
- 연구 완료·첫 제작·주택 개량·공동사업 완료는 영구 기록을 검사한다. 미리 달성했어도 인정한다.
- “보유 N개”는 현재 재고를 검사한다. “제작 N개”는 영구 제작 누계를 검사한다. “납품 N개”는 해당 주문·사업에 실제 소비한 수량만 센다.
- P0 수량형 목표는 우선 영구 제작 누계를 사용한다. 수락 이후 제작을 요구할 때만 별도 시작값을 저장하고 문구에 명시한다.
- 새 QuestGoalType은 필요한 경우 enum 끝에만 추가한다.
- E01 주문은 기존 가방 재료로 시작한다. 필수 주문은 현재 해금된 재료만 요구한다.
- P0 주문은 만료·실패 벌금 없이 수동 납품한다. 취소 시 납품 전 자재와 비용을 잃지 않는다.
- 납품과 보상 상태는 주문 ID별로 저장한다. 연속 클릭·재접속으로 소비나 보상이 반복되지 않아야 한다.
- 옛 메인 108개는 데이터와 ID를 보존하고 새 메인 선택에서 제외한다. 새 메인은 별도 ID를 쓴다.

## 6. 프롤로그와 화면

- 프롤로그 진입 조건은 Lv.20 이상 + `mine_source_removed` + `castle_built`로 제안한다. 기존 메인 순서와 원본 기획서에서 모순이 없는지 구현 전에 확인한다.
- 진입 조건을 채우면 안전한 화면 상태에서 프롤로그를 제안한다. 전투·다른 컷신 도중 강제로 시작하지 않는다.
- 30~45초 컷신에 건너뛰기를 제공한다. 완료·건너뛰기 모두 진입 기록과 기본 RP를 1회 반영한다.
- 중간 종료는 완료로 처리하지 않는다. 다음 접속에서 다시 시작할 수 있다.
- 기록관 다시 보기는 진행 상태·RP·보상을 바꾸지 않는다.
- 왕국 발전 화면은 연구·공동사업·물류·기록 4탭으로 구성한다. 아직 구현되지 않은 기능은 준비 중으로 표시하고 실행 버튼을 두지 않는다.

## 7. 저장과 기존 유저 전환

- 현재 저장 구조를 존중한다. A의 산업 데이터는 이미 `SaveData.settlement.industry`에 있으므로 이번에 다른 경로로 옮기지 않는다.
- B 데이터는 새 `SaveData.prosperity` 아래에 둔다. 연구·RP 지급 키·선지급 대응 키·의뢰·주문·프롤로그·공동사업 보상 수령·메인 전환 상태를 저장한다.
- 저장 경로가 분담서 가안과 달라진 점을 A에게 전달한다. 같은 산업 데이터를 두 위치에 복제하지 않는다.
- 현재 schemaVersion은 4다. 실제 머지 시 최신 버전을 확인하고 다음 번호에 SaveMigrations 단계를 추가한다. 현재 기준 예상 번호는 5다.
- 로드 시 누락 필드를 초기화하고, 마이그레이션은 여러 번 호출해도 결과가 같게 한다.
- 기존 유저는 시대 진입 시 기본 RP와 현재 레벨까지의 레벨 RP를 소급한다. 이번 P0에서는 Lv.27까지만 지급하며 상위 레벨분은 P1·P2 지급표가 생길 때 추가한다.
- 예: 기존 Lv.25 유저의 기본+레벨 RP는 2+5=7이다. 기존 Lv.40 유저는 P0 범위에서 2+7=9다. 각 지급 키도 함께 저장한다.
- 연구·공동사업·제작 기록은 레벨만 보고 완료 처리하지 않는다. 실제 기록이 있는 완료 보상만 지급한다.
- 기존 유저에게도 첫 공동사업과 새 연구가 열려 있어야 한다. 과거 레벨 메인 완료를 접근 조건으로 삼지 않는다.
- 이미 수령한 옛 메인의 대응 구간은 새 메인에서 보상 없는 전환 처리한다. 미수령 진행은 사라지지 않도록 전환표로 보존하고, 적용 전 구형 세이브 스냅샷을 확보한다.
- 옛 메인 ↔ 새 메인 대응표는 원본 135개 목록을 확인한 뒤 확정한다. 이 표 없이는 실제 세이브 전환을 배포하지 않는다.
- Lv.28+ 기존 유저를 미구현 메인으로 교체하지 않는다. P0 체험은 발전 화면에서 제공하고, 후기 메인 전체 전환은 P1·P2 데이터와 대응표가 준비된 뒤 적용한다.
- P0만 켜는 개발 환경에서는 옛 메인과 새 메인의 보상 경로가 겹치지 않도록 전환 모드로 격리한다.

## 8. 구현 순서와 통과 조건

1. 원본 기획서 대조 및 A 전달용 API·기록 ID 표 확정.
2. 저장 모델·RP 지급 키·연구 순수 로직 구현 및 핵심 검증.
3. TechGate 연결: 연구 후 A 기능 활성화, 저장·재접속 후 유지 확인.
4. 프롤로그·기본 RP·첫 공동사업·선지급을 연결해 RP 막힘 확인.
5. Lv.23~27 메인 25개와 E01 주문 2개 구현.
6. 왕국 발전 화면·기록관 연결.
7. 신규 Lv.20, 기존 Lv.23/27/40, 창고 가득 참, 선행 행동 완료, 재접속 사례 검증.

P0 통과 조건:

- 선지급 없이 필수 연구 7개를 모두 열 수 있고, 기본 기능 진입에 순환 조건이 없다.
- 연구가 판재·창고·수레·주택 개량으로 연결된다.
- 첫 무료 가공품과 오프라인 정산이 퀘스트를 잘못 중복 집계하지 않는다.
- 부족한 복합 비용·반복 클릭에서 부분 소비·중복 보상이 없다.
- 정산·마이그레이션을 반복해도 RP·재고·XP가 늘지 않는다.
- 기존 세이브의 XP·아이템·입주민·건물·산업 데이터가 유지된다.

## 9. A에게 우선 전달할 내용
