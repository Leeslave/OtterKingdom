# M1 밭 구현 — 작업기록

작성일: 2026-09-22
문서 성격: 클로드와의 대화에서 진행한 작업 로그. 기획 확정 문서가 아니라 **다음 작업 재개 시 참고용 기록**이다. 기획 자체는 `해달마을_클로드전달용_상세기획서.md`, `해달왕국_클로드전달용_기획변경명세.md`를 기준으로 하고, 이 문서는 그 두 기획서를 읽은 뒤 실제로 어떤 대화·결정·구현이 있었는지를 남긴다.

## 1. 이번 세션에서 확정된 사항 (기획 문서에는 아직 반영 안 됨)

기존 두 기획서를 읽고 클로드가 질문한 내용에 대해 사용자가 아래처럼 답했다. 기획서 원문은 수정하지 않았으므로, 두 기획서와 이 절이 충돌하면 **이 절이 최신**이다.

- **재화 명칭**: 재화 = `코인`. 1차 채집물(낚시) = `조개`(재화 아님, 아이템). 기존 기획서의 "조개 = 재화" 표현은 폐기.
- **모종 체계 이원화**:
  - 영구 해금형(∞, 소모 없음): 당근, 양파, 대파
  - 소모형(수량 차감): 토마토, 딸기 등
  - 게임 시작 시 당근만 해금.
- **소모형 모종 획득 경로**: 요정 NPC가 특정 날짜에 방문해 파는 방식(동물의숲 '여욱' 포지션). 아직 미구현 — 토마토/딸기를 실제로 붙이는 시점에 설계 필요.
- **씬 구조**: 밭/낚시터/광장을 별도 Unity Scene으로 분리. 전환 시 약간의 로딩은 허용.
- **입력**: 새 Input System 사용 확정 (프로젝트에 `com.unity.inputsystem 1.18.0` 설치 및 `activeInputHandler: 1`로 이미 활성화되어 있음을 확인함).
- **저장 방식**: JsonUtility, Dictionary 미사용. 클래스+List 기반, 관계는 ID로 저장.
- **1차 검증 슬라이스 범위**: 첫 밭(이미 개간됨) + 시작 해달 배치 + 당근 모종 선택 + 생산 + 저장. 밭 2번 확장은 다음 슬라이스, 낚시터/광장은 그 다음.

## 2. M1 코드 구현 (게임 로직)

밭 1개에서 당근을 심고 → 자동 생산 → 수확 → 판매 → 강화까지 가능한 최소 루프를 구현했다. 목표/튜토리얼/도감 시스템, 8시간 오프라인 캡, 단조 시계 가드는 이번 범위에서 **의도적으로 제외**했다(M3 몫).

### 추가된 스크립트

| 경로 | 역할 |
|---|---|
| `Assets/Scripts/Data/SeedType.cs` | enum: Permanent / Consumable |
| `Assets/Scripts/Data/CropDefinition.cs` | ScriptableObject: 작물 정의 (id, 이름, 생산시간, 수량, 가격, seedType) |
| `Assets/Scripts/Data/FarmBalanceData.cs` | ScriptableObject: 저장 상한 회차, 레벨별 강화 비용/시간 배율 |
| `Assets/Scripts/Farm/PlotState.cs` | enum: Locked/Idle/Producing/Full |
| `Assets/Scripts/Farm/PlotRuntime.cs` | 밭 1개의 생산 로직 (Tick, Harvest, SelectCrop). 오프라인 캐치업까지 같은 Tick으로 처리 |
| `Assets/Scripts/Farm/FarmService.cs` | 여러 밭을 관리하는 상위 서비스, 레벨별 배율 적용 |
| `Assets/Scripts/Inventory/InventoryService.cs` | 가방(itemId→수량) |
| `Assets/Scripts/Economy/EconomyService.cs` | 코인 잔액, 전체 판매 |
| `Assets/Scripts/Save/SaveData.cs` | 세이브 스키마 (List 기반, Dictionary 없음) |
| `Assets/Scripts/Save/SaveService.cs` | JsonUtility 저장/로드, temp파일→백업→교체 |
| `Assets/Scripts/GameManager.cs` | 부트스트랩 + 서비스 연결 + (임시) OnGUI 디버그 패널 |

### 알아둘 설계 포인트

- 강화는 **다음 생산 주기부터만** 적용된다 (`PlotRuntime.ComputeDuration`이 새 사이클 시작 시점에만 호출됨). 진행 중인 사이클의 `remainingSec`은 그대로 유지.
- 수확은 부분 수확 없이 밭의 저장소 전체를 가져가며, 진행 중인 사이클은 건드리지 않는다.
- 저장소 상한(기본 6회분)에 도달하면 생산 중단, 수확 후 자동 재시작.
- 오프라인/온라인 구분 없이 `PlotRuntime.Tick(deltaSeconds, multiplier)`가 큰 deltaSeconds도 그대로 처리(while 루프로 여러 사이클 완료). 단, **8시간 캡·시계 조작 방어는 아직 없음** — 지금은 앱을 며칠 꺼놔도 그만큼 다 생산된 것으로 계산됨.
- `CropDefinition`/`FarmBalanceData`를 Inspector에 안 꽂아도 코드 안 기본값(당근 하나, 강화 비용 30/150/500/1200, 배율 1.0~0.6)으로 동작하게 만들어서 에디터 설정 없이 바로 테스트 가능하게 했다.

## 3. Farm 씬 아트 반입

사용자가 4장의 이미지를 제공: 밭고랑 활성 이미지, 밭고랑 잠금(점선) 이미지, 빈 배경(9:16), 밭 3개가 배치된 참고 목업(최종 배치 예시).

### 반입한 에셋

| 파일 | 원본 | 용도 |
|---|---|---|
| `Assets/Art/Farm/farm_background.png` | 빈 배경 이미지 | Farm 씬 배경, 941×1672px (9:16) |
| `Assets/Art/Farm/plot_active.png` | 밭고랑 활성 이미지 | 해금된 밭 |
| `Assets/Art/Farm/plot_locked.png` | 밭고랑 점선 이미지 | 잠긴 밭 |

세 파일 모두 Sprite import, **Pixels Per Unit = 104.5**로 통일 (배경 941px 폭 기준 world width ≈ 9 유닛, height = 16 유닛이 되도록 역산한 값). 이 PPU를 기준으로 참고 목업 이미지의 밭 3개 픽셀 위치를 측정해서 월드 좌표/스케일로 환산해 배치했다 (계산 스크립트는 세션에만 있었고 레포에는 남기지 않음 — 좌표를 다시 뽑아야 하면 목업 이미지를 다시 픽셀 분석해야 함, 원본 목업 자체는 레포에 커밋하지 않았다).

### Farm.unity 배치 결과

- Main Camera: Orthographic Size 5 → **8**로 변경 (배경 높이 16유닛에 맞춤)
- `Background`: `farm_background.png`, position (0,0,0), sortingOrder -10
- `Plot_1_Active`: `plot_active.png`, position (0.3254, 1.933, 0), scale (0.3667, 0.3263), **활성 밭 (맨 위)**
- `Plot_2_Locked`: `plot_locked.png`, position (0.2727, -0.201, 0), scale (0.3972, 0.3839)
- `Plot_3_Locked`: `plot_locked.png`, position (0.1866, -2.5502, 0), scale (0.4185, 0.4046)

기획대로 "맨 위 1개 = 활성(M1에서 제공하는 밭), 아래 2개 = 잠김"으로 배치했다. 잠긴 두 밭은 아직 해금 로직과 연결되어 있지 않다 (비주얼만 존재).

⚠️ 텍스처 .meta 파일(TextureImporter 설정)과 Farm.unity 씬 파일을 클로드가 텍스트로 직접 작성했다. 이후 사용자가 에디터를 열었을 때 Unity가 .meta를 스스로 재직렬화한 흔적(플랫폼별 설정 자동 채움)이 확인되어 정상 임포트된 것으로 보인다.

## 4. 밭 클릭 → 디버그 패널 토글

"활성화된 밭을 누르면 UI가 뜨고, 다시 누르면 꺼진다"는 요청으로 아래를 구현:

- `GameManager`: `showDebugPanel` 필드를 추가해 **기본값 숨김**으로 변경. `ToggleDebugPanel()` 공개 메서드, `DebugPanelRect` 공개 상수 추가.
- `Assets/Scripts/View/PlotClickToggle.cs` (신규): 새 Input System의 `Pointer.current`로 마우스/터치를 하나의 코드로 처리. `Physics2D.OverlapPoint`로 클릭 좌표가 해당 오브젝트 위인지 판정 후 토글 호출. 패널이 열려 있을 때 클릭 좌표가 `DebugPanelRect` 안이면 무시(패널 버튼 클릭이 동시에 밭 클릭으로 판정되어 즉시 닫히는 문제 방지).
- `Plot_1_Active`에만 `BoxCollider2D`(트리거) + `PlotClickToggle` 컴포넌트 부착. 잠긴 밭에는 아무 것도 없음 — 해금 인터랙션은 후속 작업.

## 5. 아직 안 한 것 / 다음 후보

- 비주얼(밭 스프라이트)과 실제 게임 로직(`FarmService`/`PlotSaveData`)이 아직 연결 안 됨 — 성장 단계 표시, 수확 연출, 잠금 해제 시 스프라이트 교체 등 전부 미구현.
- 밭 2·3번 개방 로직, 해달 배치 UI, 목표/튜토리얼, 도감, 8시간 오프라인 캡, 시계 조작 방어, 낚시/광장 전부 미착수.
- 이번 세션에서 만든 것들은 **Unity 에디터에서 직접 Play 눌러 검증한 적 없음** (클로드가 에디터를 실행할 수 없는 환경). 다음 재개 시 실제 동작 확인 결과부터 공유하면 좋다.
- 다른 세션에서 진행된 작업(해달 애니메이션 관련, `농부해달_애니메이션_작업기록.md` 참고)과의 통합은 아직 검토 안 함 — 밭 씬에 해달 애니메이션을 배치하려면 그 문서도 같이 봐야 한다.
