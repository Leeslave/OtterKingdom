## 후속 — 첫 공동사업·선지급 의뢰

### 구현됨

- 첫 사업 `prosperity_plan_01` / 번영 계획 수립: 시대 진입 후 목재(material_wood) 12개와 돌(ore_stone) 12개를 납품하고 계획을 확정한다. 연구·가공품·이전 공동사업 완료를 요구하지 않는다. 비용은 P0 임시값이다.
- 기존 CommunityProjectRules의 부분 납품·단계·완료·저장을 재사용한다. 신규 사업은 별도 등록하므로 기존 P3 순차 사업이나 무한 반복 사업이 막지 않는다.
- ProjectActionKind 끝에 ConfirmPlan(6)을 추가했다. 계획 확정은 첫 마을 모임과 별도 기록이며 모임 연출·다시 보기·모임 보상에 영향을 주지 않는다.
- 실제 사업 완료 기록을 확인해 3 RP를 1회 지급한다. 사업 완료만 저장되고 RP 지급 직전에 종료된 경우에도 다음 로드에서 누락 보상을 복원한다.
- 선지급 의뢰 2종: 수락 후 작물 30개 수확 / 판매로 1,000골드 벌기. 한 번에 한 의뢰, 각 종류 1회, 보상은 1 RP씩이다.
- 선지급은 Lv.26 → Lv.27 순서로 미수령 레벨 지급 키를 사용한다. 도달 시 중복 지급하지 않으며 P0 총 RP 공급은 선지급 여부와 무관하게 12다.
- 의뢰 취소 시 진행을 초기화하고 RP·자재를 차감하지 않는다. 수령 전에 대응 레벨에 도달하면 정상 레벨 보상을 지급하고 해당 의뢰는 종료한다. Lv.27+는 선지급 대상이 아니다.
- 실제 Harvest 양수 이벤트와 판매 이벤트만 연결했다. 로드·구매·환불·생산·수레 이동은 수확 의뢰에 포함하지 않는다. 수락한 의뢰는 오프라인 수확도 같은 경로로 집계한다.
- 의뢰 진행과 완료 종류는 prosperity에 추가 저장하며, 이전 schema 5의 누락 목록은 sanitizer에서 초기화한다. 기존 필드나 저장 경로를 바꾸지 않아 스키마 번호는 5를 유지한다.
- 가방 처리 도중의 의뢰 진행은 프레임 말에 저장하고, 여러 획득에 따른 화면 갱신도 프레임당 한 번으로 묶었다.
- 왕국 발전 4탭 연결: 연구 / 공동사업(선지급 의뢰 포함) / 물류(기존 일터·창고 열기) / 기록(완료 연구·계획·선지급 기록).

### 검증

- 런타임·전체 테스트 소스 컴파일 성공.
- .NET 연구·RP·마이그레이션 검사 27개 통과. 선지급 순서를 바꿔도 총 공급 12 RP 유지, 레벨업과 수령 경합, 취소·재수락·재접속·중복 수령·잘못된 저장값을 포함한다.

- 실제 화면·클릭·씬 이동·JsonUtility 왕복 역시 Unity 환경에서 확인해야 한다. 앞선 Package Manager IPC 오류는 이번 작업에서 해결하지 않았다.

## 2026-11-04 — E01 장터 주문

### 구현됨

- E01 연구 제한 해제. Lv.21·I01·1 RP 조건으로 연구하면 기존 가방 재료를 납품할 수 있다.
- 초도 주문 2개를 각 1회 제공한다. 당근(crop_carrot) 12개 → 90골드, 목재(material_wood) 20개 → 75골드. 기존 기본 판매가 대비 약 25%를 더 주는 임시 보상이며 RP·XP·조개는 지급하지 않는다.
- 수락 → 전량 납품과 보상 수령 → 완료의 흐름. 만료·실패 벌금·자동 납품은 없고, 납품 전 취소는 비용이 없다. 이미 보유한 가방 재료도 바로 사용할 수 있다.
- 수락·완료 주문 ID를 prosperity에 저장한다. schema 5에서 새 필드가 누락된 세이브는 빈 목록으로 초기화한다. 완료와 수락 양쪽에 같은 ID가 있으면 완료를 우선한다.
- 납품 버튼에서 연구·레벨·수락 상태·보유량·골드 보유 상한을 다시 확인한다. 재료 부족이나 전액 보상 수령 불가 시 아무것도 소비하지 않는다.
- 납품 도중 이벤트로 동일·다른 주문을 다시 납품하거나 취소하지 못하게 한다. 성공한 주문만 완료 기록을 남긴다.
- 가방 차감·골드 지급 이벤트에서 저장을 요청하더라도 ProsperitySaveGate가 거래 끝까지 미뤄 최종 상태를 한 번 저장한다. 실패해서 아무 변화가 없으면 불필요한 저장을 만들지 않는다.
- 골드 출처는 TransactionSource 끝에 추가한 MarketOrderReward다. 납품은 ItemChangeReason.Delivery를 사용하고 OnItemSold를 발생시키지 않으므로 판매 퀘스트·판매 선지급 실적을 중복 올리지 않는다.
- 연구 탭에 장터 주문 목록과 보유량·보상·수락·취소·납품 버튼을 추가하고, 기록 탭에 완료 주문을 표시한다. 화면이 열려 있을 때 가방·골드 변경도 반영한다.

## 2026-11-04 — 가스 사건 이후 자동 연결·기존 세이브 복구

### 확인한 문제

- 실제 Lv.21 세이브에는 가스 제거·성 완공 기록이 있었지만 introCompleted=false, RP=0, 연구 목록이 비어 있었다.
- 시대 시작이 회관의 수동 버튼에만 연결되어 정상 진행 중에는 새 기능을 발견하기 어려웠다.

### 수정

- schema 6 전환 추가. 과거 mineMaze.community.sourceRemoved와 성 건설 완료 부탁 기록에서 발전 기록이 누락됐으면 보완한다. 레벨만 보고 완료를 만들어 주지는 않는다.
- sanitizer에서도 같은 멱등 보정을 적용해 기존 저장 버전과 복원 시점에 관계없이 실제 완료 기록이 연결된다.
- 조건을 마친 기존·신규 플레이어가 광장에 오면 도입 안내를 자동으로 시작한다. 가스는 해결했지만 성이 없으면 성 준비 화면으로 안내한다.
- 장소 이동·열린 창·레벨업·다른 튜토리얼·알림이 끝날 때까지 기다린다. 안내 도중 씬 이동·종료로 중단되면 완료 표시를 남기지 않고 다음 광장에서 다시 시작한다.
- 도입 안내 완료·건너뛰기에서 시대 진입과 RP 소급을 한 번 처리하고 첫 연구 화면을 연다. 현재 Lv.21 사례는 총 3 RP를 받는다.
- 이미 시작한 세이브에는 도입을 반복하지 않는다. 연구·사용한 RP·가방·골드·건물·산업 기록을 유지한다.
- 발전 화면에 “다음 발전” 카드를 추가했다. 제재 연구 → 목공소 첫 판재 → 번영 계획 공동사업 → 공동 창고 연구로 이어지며 기록이 있으면 해당 단계를 건너뛴다.
- 광장에서도 다음 행동을 알림과 바로 가기로 제안한다. 연구 화면은 항상 연구 탭으로 진입하며, 다음 발전 카드에서 첫 연구를 바로 실행할 수 있다.
- 플레이어의 실제 save.json을 직접 수정하지 않았다. 새 코드로 기존 세이브를 다시 불러올 때 적용된다.

### 검증

- .NET 연구·진행·경제·마이그레이션 검사 55개 통과. schema 0~5, 현재 schema 6의 누락 기록, Lv.19/20/21/27/40/50, 기존 연구·RP 보존을 포함한다.
- Unity에서 1차 세이브·진행 검사 30개 통과. 제한된 실행 환경의 Package Manager IPC 오류는 사용자 캐시·IPC 접근이 가능한 실행으로 해소했다.
- 실제 Unity UI 생성과 JsonUtility 왕복을 확인하는 별도 테스트를 추가했다. 테스트는 임시 씬과 메모리 상태만 사용하며 플레이어 세이브를 읽거나 쓰지 않는다.
- Unity 최종 검증: 기존 연구·RP·장터·이전 저장·공동사업 79개 통과, 자동 안내 UI·저장 왕복 2개 통과(총 81개). UI 테스트는 Test Runner 임시 씬에서 완료·건너뛰기 콜백과 화면 생성을 검증한다.
- 결과: `tmp/prosperity-onboarding-final-results.xml`의 회귀 79개와 `tmp/prosperity-onboarding-ui3-results.xml`의 UI·저장 2개. 최초 UI 테스트의 EditMode 씬·수명주기 설정 오류를 수정한 후 별도 재실행했다.

재현: 기존 Lv.21 세이브를 그대로 다시 불러와 광장으로 돌아온 뒤, 다른 안내가 끝나면 도입 안내가 열린다. 완료하거나 건너뛰면 3 RP와 첫 연구 화면을 제공한다. 새 게임이나 수동 세이브 편집은 필요 없다.

이 작업은 시작 안내와 초반 기능 연결을 보완한다. Lv.23~27 메인 25개 교체와 기존 메인 전환은 별도 작업으로 남아 있다.
