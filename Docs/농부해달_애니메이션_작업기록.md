# 농부 해달 — 캐릭터 애니메이션 작업기록

작성일: 2026-09-22
문서 성격: 클로드와 진행한 캐릭터 애니메이션 작업 세션 기록. 다음에 이어서 작업할 때 참고용.

## 1. 요청 배경

평상시에는 밭 주변을 돌아다니다가, 수확이 가능해지면 해당 밭고랑으로 이동해서 수확을 진행하는 농부 해달 NPC를 만들고 싶어함. 이번 세션에서는 그 첫 단계로 **애니메이션 클립부터** 구현했다. 배회·이동 AI 로직은 아직 손대지 않았다.

## 2. 원본 스프라이트 시트 분석

- 파일: `Assets/Sprites/Characters/FarmerOtter/FarmerOtter_Sheet.png`
- 크기: 1448 x 1086, 8열 x 5행 그리드 (칸당 181 x 217.2px)
- 알파 채널 투영으로 행 경계를 확인해 그리드임을 검증함 (칼럼은 프레임끼리 겹쳐서 경계 검출 안 됨 — 8칸 균등 분할로 처리)

행별 내용 (위에서부터):

| 행 | 클립 이름 | 내용 |
|---|---|---|
| 1 | Walk | 측면(오른쪽 보는 방향) 보행 8프레임 |
| 2 | Walk_Alt | 측면 보행 변형 8프레임 — 용도 미정 (Run일 수도, 단순 변형일 수도) |
| 3 | Idle | 정면(카메라 보는 방향) 대기 8프레임 |
| 4 | Idle_Back | 후면(등 보이는 방향) 대기 8프레임 |
| 5 | Harvest | 새싹/작물을 손에 드는 동작 8프레임 — 수확 연출에 사용 |

왼쪽 방향 프레임은 시트에 없음. 좌우 이동은 `SpriteRenderer.flipX`로 미러링해서 처리하는 걸 전제로 함 (아직 구현 안 함).

## 3. 만든 것 — 에디터 도구

`Assets/Editor/FarmerOtterSpriteSetup.cs`

Unity 메뉴 **`OtterKingdom > Tools > Setup Farmer Otter Animations`** 를 실행하면:

1. `FarmerOtter_Sheet.png`를 8x5 Multiple 스프라이트로 슬라이싱 (PPU 100)
2. `Assets/Animations/FarmerOtter/` 에 애니메이션 클립 5개 생성 (Walk, Walk_Alt, Idle, Idle_Back, Harvest — 프레임레이트 10fps, 모두 loop)
3. `Assets/Animations/FarmerOtter/FarmerOtter.controller` 생성
   - 파라미터: `IsMoving` (bool), `Harvest` (trigger)
   - Idle ↔ Walk: `IsMoving` 값으로 전환
   - Any State → Harvest: `Harvest` 트리거로 전환, 클립 1회 재생 후 자동으로 Idle 복귀
   - Walk_Alt, Idle_Back은 클립 에셋으로만 존재, 컨트롤러에는 아직 연결 안 함
4. `Assets/Prefabs/FarmerOtter.prefab` 생성 (SpriteRenderer + Animator 세팅 완료, 기본 스프라이트는 Idle 첫 프레임)

배치 모드(CLI)로 직접 돌리려다 이미 열려있는 Unity 에디터와 충돌해서, 메뉴 아이템 방식으로 바꿔서 사용자가 열려있는 에디터에서 직접 실행하는 방식으로 처리함.

**세션 종료 시점 기준 상태: 사용자가 아직 메뉴를 실행하지 않음 (Assets/Animations, Assets/Prefabs 폴더 미생성).** 다음에 이어서 할 때 먼저 이 메뉴 실행 여부부터 확인할 것.

## 4. 남은 작업 / 미정 사항

- **배회(Wander) 로직 없음**: 밭 주변을 돌아다니는 이동 스크립트 미구현.
- **밭의 씬 좌표 개념이 아직 없음**: `PlotRuntime`/`PlotState`는 순수 데이터(C# 클래스)일 뿐 Transform이나 월드 위치를 갖지 않음. 수확 시점에 "해당 밭고랑으로 이동"하려면 밭마다 씬 상의 목표 지점(Transform이나 좌표)을 먼저 설계해야 함.
- **Walk_Alt, Idle_Back 용도 미정**: 나중에 4방향 이동을 만들 때 쓸지, 그냥 예비 소재로 둘지 결정 필요.
- **Harvest 애니메이션 트리거 시점 미정**: `FarmService.Harvest()` 호출과 애니메이션 재생을 어떻게 동기화할지 (즉시 수확 vs 애니메이션 재생 후 수확 등) 아직 설계 안 함.
- 에디터 도구(`FarmerOtterSpriteSetup.cs`)는 일회성 도구 성격이 강함 — 계속 쓸 계획이면 유지, 아니면 실행 후 정리 고려.

## 6. 스프라이트 재적용 (2026-09-26)

### 문제
- 걷기와 랜덤 동작의 캐릭터 크기가 달랐음: 기존 걷기 프레임은 약 171px, 랜덤 동작 시트는 약 209px였는데 둘 다 PPU 100으로 들어가서 20%쯤 차이 남.
- AI가 생성한 시트는 정확한 그리드가 아니라서 캐릭터가 칸 경계를 넘어감 → 균등 분할로 자르면 옆·위아래 프레임 조각이 같이 잘려 들어가고, 프레임마다 위치가 흔들림 ("깨짐").

### 해결 — 오프라인 재패킹
`Tools/SpriteRepack/repack_farmer_otter.py` (Python + Pillow/NumPy/SciPy)로 새로 받은 시트 5장을 전처리해서 `Assets/Sprites/Characters/FarmerOtter/`에 덮어씀.
1. 알파 연결 성분으로 캐릭터를 프레임 단위로 추출 (붙어 있는 행은 가장 빈 가로줄에서 잘라냄, 모션 라인 같은 작은 조각은 가장 가까운 프레임에 붙임)
2. 시트별 기준 포즈(서 있는 측면 프레임)의 키 + 모자 폭으로 스케일을 계산해 모든 시트의 캐릭터 크기를 통일
3. 발 바닥은 공통 기준선, 모자 중심은 칸 가운데 열에 맞춰서 416x240 균등 칸에 다시 배치 (칸마다 투명 여백 포함)

원본 시트를 다시 받으면 `images/1~5.png` 경로만 맞춰서 스크립트를 다시 돌리면 됨. 칸 크기가 바뀌면 `FarmerOtterSpriteSetup.cs`의 `CellW/CellH`도 같이 수정할 것.

### 새 시트 구성
| 파일 | 행 구성 |
|---|---|
| FarmerOtter_Sheet.png | 오른쪽 걷기 / 왼쪽 걷기 / 정면(아래) 걷기 / 뒷모습(위) 걷기 / 수확 |
| FarmerOtter_IdleAction_{Net,Stretch,Eat,Squat}.png | 오른쪽 / 왼쪽 / 정면 / 뒷모습 (Squat = 쪼그려 앉았다 일어나 엉덩이 털기, 신규) |

### 애니메이터 변경
- 메인 시트에 서 있는 행이 없어져서 Idle은 수확 0번 프레임(측면 중립 포즈) 1장짜리 클립으로 바꿈. 랜덤 동작이 전부 측면이라 Idle도 측면이어야 전환할 때 방향이 튀지 않음.
- `WalkDir` int 파라미터 추가 (0 = 측면, 1 = 아래, 2 = 위). 세로로 이동할 때는 정면/뒷모습 걷기, 가로로 이동할 때는 측면 걷기 + flipX.
- 랜덤 동작에 `Squat` 추가 (씬의 `randomActionTriggers`에도 추가함).
- PPU 120으로 기존 걷기와 같은 화면 크기를 유지.
- 프리팹은 지우고 다시 만들지 않고 제자리에서 갱신하도록 바꿈 (다시 만들면 씬 인스턴스 오버라이드와 웨이포인트 연결이 깨짐).
