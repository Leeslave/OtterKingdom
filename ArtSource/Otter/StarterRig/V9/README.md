# 처음 해달 — 확정 V9 기준 적용

2026-10-13 사용자 지시: “그 V9 우리 기준 대로 만들어줘”. 처음 만든 정면 리그 대신 확정 V9의 앞쪽 오른쪽 ¾뷰와 걷기 구조를 적용한다.

## 기준과 적용

기준은 `ArtSource/Otter/QuarterRig/BASELINE.md`에서 지정한 `Baseline-V9/` 3개 파일이다. 후속 V10~V14를 기준으로 사용하지 않았다. 기준 원본 파일은 변경하지 않았다.

- `pose`, `legPose`: 고정 V9 HTML에서 그대로 재사용. 검증 스크립트에서 함수 텍스트 동일성 확인.
- 0.84초 주기, 디딤 비율 0.6, 반 보폭 6px, 발 들기 6px.
- 다리 60×76px, 가까운 다리 X=-16, 먼 다리 X=31, 회전 진폭 0.025rad.
- 관절 위치/피벗/부모/레이어/표시 폭은 V9와 동일. 새 파츠의 표시 높이도 V9 이미지 비율로 맞춤.
- 다리는 V9처럼 발바닥을 기준으로 움직이고 상부는 일자 형태로 렌더링. 기존 바지색을 털색으로 바꿈. 이는 다리 원화를 통째로 출력하는 방식과 다르며 `drawLeg`를 참고.
- 주인공은 맨몸 기본형이므로 모자/옷/가방 없음. 가방 표시 파츠만 제외하고 연결점은 유지. 얼굴/체형 선택 기능 없음.

새 ¾뷰 파츠는 콘셉트와 V9 캡처를 참조하여 built-in image_gen으로 생성했다. 이전 정면 PNG를 회전/왜곡해 ¾뷰로 만든 것이 아니다. 원본 콘셉트의 픽셀 동일성을 보장하는 작업은 아니다. 프롬프트는 `PROMPT.md`.

## 파일

- `preview.html`: 자체 이미지 내장, 브라우저에서 직접 열기. 대기/걷기/좌우 반전/관절/분해/게임 크기 확인.
- `walk.gif`: V9 주기의 24프레임 걷기 미리보기.
- `walk-phases.png`: 4개 위상의 동작 확인.
- `parts-atlas.png`, `parts/`: 투명 원화와 5개 추출 PNG. 팔과 다리는 가까운 쪽/먼 쪽에 공유.
- `rig.json`: 기준 관절, 다리 제어값, 착용물 슬롯, 원화 영역.
- `provenance.json`: 기준 원본 3개의 SHA-256 및 적용 차이.
- `verification.json`: 기준 일치/접지/브라우저 검증 기록.

## 검증

기준 리깅 수치 일치, 걷기 함수 텍스트 일치, 관절 좌표/피벗/레이어 일치, 기준 파일 해시 불변을 확인했다. 0/50/100/150% 보폭의 808개 디딤 표본에서 접지 Y 오차 0, 바닥 속도 대비 최대 속도 오차 약 1.2e-9였다. 걷기 24프레임을 렌더링하고 주요 4개 위상과 최종 모습을 눈으로 확인했다. Edge headless에서 조작/390px 화면/페이지 오류도 검사했다.

접지 검증은 V9 다리 기준점과 이동하는 바닥 간 계산이다. 실제 Unity 월드의 이동, 충돌, 물리나 애니메이션 전환을 검증한 것은 아니다. 좌우 반전 시 바닥 격자 연출도 V9 원본과 동일하다.

## 재생성

`sharp`, `playwright` 사용. Node 패키지 경로를 설정한 뒤 저장소 루트에서 실행:

```powershell
node Tools/StarterOtterRig/build-v9.cjs
node Tools/StarterOtterRig/verify-v9.cjs
```

정면 초기 작업은 상위 `StarterRig/`에 보존되어 있다. 사용자 피드백의 현재 기준 결과물은 이 `V9/preview.html`이다. 측면/뒷면 추가 및 Unity 연결은 아직 하지 않았다.

## 위치·크기 조절 패널
오른쪽 ‘몸 조절하기’에서 앞/뒤 팔, 앞/뒤 발·다리, 몸통, 머리, 꼬리를 선택해 위치와 가로·세로 크기를 조절한다. 발끝 크기는 다리 전체 크기와 별도로 조절한다. 크기 변경은 그림만 조절하며 자식 관절 위치를 자동 확대하지 않는다. 위치 변경은 해당 부위 및 자식 부위에 적용된다. +Y는 아래이며 좌우 반전 시 X 방향도 반전된다.
변경은 브라우저 localStorage에 저장되며 원본 rig.json은 바뀌지 않는다. JSON 내보내기/불러오기와 부위별/전체 초기화를 지원한다. 브라우저별 저장은 공유되지 않을 수 있으므로 전달용은 설정 내보내기를 쓴다. 발 높이를 바꾸면 바닥 기준선에서도 같은 만큼 이동한다. 검증 결과: tuning-verification.json.

## 사용자 설정 적용 · 의상 피팅
2026-10-13: approved-settings.json에 전달받은 설정을 보존. 앞팔 +46/+5, 몸통 80%/94%, 꼬리 75%/93%를 시작값과 초기화 기준으로 적용했다. 기존 V9 원본은 그대로다. 새 저장 키로 이전 기본 설정과 구분한다. 다리 roundRect 모서리 반경을 너비 34%/높이 22% 중 작은 값으로 변경했다. 보폭과 주기는 유지한다.
wardrobe.js는 Canvas 코드로 그리는 착용 위치 확인용 모자/조끼/바지 샘플과 사용자의 PNG 착용을 제공한다. 이미지 생성 에셋이 아니라 조절 가능한 벡터 샘플이다. 상의 PNG는 소매 없는 몸통, 하의 PNG는 한쪽 바짓단으로 양다리에 공유하며 허리 연결부는 지정색으로 그린다. 모자는 머리, 상의는 몸통, 바짓단은 각각의 접지 다리에 연결된다. 하의 위치/크기 조절은 바짓단에 적용되고 허리는 몸통에 붙어 있다.
부위별 색상, 위치, 가로/세로 크기, 회전, 업로드/벗기/초기화 지원. 파일은 PNG 3MB/4096px 이하. 브라우저 자동 저장이 용량 제한으로 실패하면 메시지를 띄운다. 몸·의상 저장은 version 2 JSON이며 PNG 데이터를 포함한다. 이전 version 1 몸 설정은 몸 조절 패널에서 계속 불러올 수 있다. 큰 체형·의상 변경에는 겹침이 생길 수 있어 피팅 조절이 필요하다.
검증: approved 설정, 초기화, 샘플 렌더, 걷기 24프레임, 3개 PNG 슬롯 업로드, 위치 조절, PNG 포함 내보내기/가져오기, 새로고침 복원, 잘못된 입력 보존, 모바일 화면. 결과 wardrobe-verification.json, 캡처 approved-rounded.png/sample-outfit.png, 애니메이션 outfit-walk.gif. 기존 verify-v9 및 verify-tuning은 변경 전 기본값을 검증하므로 현 버전 검증에는 verify-wardrobe.cjs를 쓴다.
